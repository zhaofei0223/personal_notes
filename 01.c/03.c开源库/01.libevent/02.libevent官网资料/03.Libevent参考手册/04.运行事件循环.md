## 运行循环

一旦您拥有一个注册了一些事件的 event_base（请参阅下一节，了解如何创建和注册事件），您就会希望 Libevent 等待事件并向您发出警报。

**Interface**
```c
#define EVLOOP_ONCE             0x01
#define EVLOOP_NONBLOCK         0x02
// EVLOOP_NO_EXIT_ON_EMPTY existed since Libevent 2.1
#define EVLOOP_NO_EXIT_ON_EMPTY 0x04

int event_base_loop(struct event_base *base, int flags);
```

默认情况下，`event_base_loop()` 函数会运行一个 `event_base` 循环，直到其中没有更多已注册的事件为止。为了运行循环，它会反复检查已注册的事件是否已触发（例如，读取事件的文件描述符是否已准备好读取，或者超时事件的超时时间是否即将到期）。一旦触发，它会将所有已触发的事件标记为“活动”，并开始运行它们。

您可以通过在其flags参数中设置一个或多个标志来改变 event_base_loop() 的行为。如果设置了 EVLOOP_ONCE，则循环会等待直到有事件变为活动状态，然后运行活动事件直到没有更多事件可运行，最后返回。如果设置了 EVLOOP_NONBLOCK，则循环不会等待事件触发：它只会检查是否有任何事件可以立即触发，如果有，则运行它们的回调函数。

通常情况下，循环会在没有待处理或活动事件时立即退出。您可以通过传递 `EVLOOP_NO_EXIT_ON_EMPTY` 标志来覆盖此行为——例如，如果您要从其他线程添加事件。如果您设置了 `EVLOOP_NO_EXIT_ON_EMPTY`，循环将持续运行，直到有人调用 `event_base_loopbreak()` 或 `event_base_loopexit()`，或者发生错误为止。

当完成时，event_base_loop() 返回 0（如果它正常退出），-1（如果它由于后端未处理的错误而退出），1（如果它因为没有更多待处理或活动事件而退出）。

为了便于理解，以下是 event_base_loop 算法的简要概述：

伪代码
```c
while (any events are registered with the loop,
        or EVLOOP_NO_EXIT_ON_EMPTY was set) {

    if (EVLOOP_NONBLOCK was set, or any events are already active)
        If any registered events have triggered, mark them active.
    else
        Wait until at least one event has triggered, and mark it active.

    for (p = 0; p < n_priorities; ++p) {
       if (any event with priority of p is active) {
          Run all active events with priority of p.
          break; /* Do not run any events of a less important priority */
       }
    }

    if (EVLOOP_ONCE was set or EVLOOP_NONBLOCK was set)
       break;
}
```

为方便起见，您也可以拨打以下电话：

**Interface**
```c
int event_base_dispatch(struct event_base *base);
```

`event_base_dispatch()` 调用与 `event_base_loop()` 调用相同，只是没有设置任何标志。因此，它会一直运行，直到没有更多已注册的事件，或者直到调用 `event_base_loopbreak()` 或 `event_base_loopexit()` 为止。

这些函数定义在 <event2/event.h> 中。它们自 Libevent 1.0 版本以来就已存在。

## 停止循环

如果你想让一个活动事件循环在所有事件被移除之前停止运行，你可以调用两个略有不同的函数。

**Interface**
```c
int event_base_loopexit(struct event_base *base,
                        const struct timeval *tv);
int event_base_loopbreak(struct event_base *base);
```

`event_base_loopexit()` 函数指示 `event_base` 在指定时间过后停止循环。如果`tv`参数为 `NULL`，则 `event_base` 会立即停止循环。如果 `event_base` 当前正在运行任何活动事件的回调函数，它将继续运行这些回调函数，直到所有回调函数都运行完毕才会退出。

`event_base_loopbreak()` 函数指示 `event_base` 立即退出其循环。它与 `event_base_loopexit(base, NULL)` 的区别在于，如果 `event_base` 当前正在处理任何活动事件的回调函数，它会在完成当前正在处理的事件后立即退出。

另请注意，当没有事件循环运行时，event_base_loopexit(base,NULL) 和 event_base_loopbreak(base) 的行为有所不同：loopexit 会安排事件循环的下一个实例在下一轮回调运行后立即停止（就像使用 EVLOOP_ONCE 调用一样），而 loopbreak 只会停止当前正在运行的循环，如果事件循环没有运行，则不会产生任何效果。

这两种方法成功时都返回 0，失败时返回 -1。

例如：立即关闭
```c
#include <event2/event.h>

/* Here's a callback function that calls loopbreak */
void cb(int sock, short what, void *arg)
{
    struct event_base *base = arg;
    event_base_loopbreak(base);
}

void main_loop(struct event_base *base, evutil_socket_t watchdog_fd)
{
    struct event *watchdog_event;

    /* Construct a new event to trigger whenever there are any bytes to
       read from a watchdog socket.  When that happens, we'll call the
       cb function, which will make the loop exit immediately without
       running any other active events at all.
     */
    watchdog_event = event_new(base, watchdog_fd, EV_READ, cb, base);

    event_add(watchdog_event, NULL);

    event_base_dispatch(base);
}
```

例如：运行事件循环 10 秒钟，然后退出。
```c
#include <event2/event.h>

void run_base_with_ticks(struct event_base *base)
{
  struct timeval ten_sec;

  ten_sec.tv_sec = 10;
  ten_sec.tv_usec = 0;

  /* Now we run the event_base for a series of 10-second intervals, printing
     "Tick" after each.  For a much better way to implement a 10-second
     timer, see the section below about persistent timer events. */
  while (1) {
     /* This schedules an exit ten seconds from now. */
     event_base_loopexit(base, &ten_sec);

     event_base_dispatch(base);
     puts("Tick");
  }
}
```

有时您可能需要判断对 event_base_dispatch() 或 event_base_loop() 的调用是正常退出，还是因为调用了 event_base_loopexit() 或 event_base_break() 而退出。您可以使用以下函数来判断 loopexit 或 break 是否被调用：

**Interface**
```c
int event_base_got_exit(struct event_base *base);
int event_base_got_break(struct event_base *base);
```

如果循环分别因 event_base_loopexit() 或 event_base_break() 而停止，这两个函数将分别返回 true 或 false。下次启动事件循环时，它们的值将被重置。

这些函数在 <event2/event.h> 中声明。event_break_loopexit() 函数最初在 Libevent 1.0c 中实现；event_break_loopbreak() 函数最初在 Libevent 1.4.3 中实现。

## 重新检查事件

通常情况下，Libevent 会检查事件，然后按优先级运行所有活跃事件，之后再次检查事件，如此循环往复。但有时你可能希望在当前回调函数运行完毕后立即停止 Libevent，并指示它重新开始扫描。类似于 `event_base_loopbreak()` 函数，你可以使用 `event_base_loopcontinue()` 函数来实现这一点。

**Interface**
```c
int event_base_loopcontinue(struct event_base *);
```

如果当前没有运行事件回调，则调用 event_base_loopcontinue() 不会产生任何效果。

此功能是在 Libevent 2.1.2-alpha 中引入的。

## 检查内部时间缓存

有时你想在事件回调中大致了解当前时间，但又不想自己调用 gettimeofday()（大概是因为你的操作系统将 gettimeofday() 实现为系统调用，而你想避免系统调用开销）。

在回调函数内部，您可以向 Libevent 询问它开始执行此轮回调函数时的当前时间：

**Interface**
```c
int event_base_gettimeofday_cached(struct event_base *base,
    struct timeval *tv_out);
```

如果 event_base 当前正在执行回调函数，则 event_base_gettimeofday_cached() 函数会将tv_out参数的值设置 为缓存时间。否则，它会调用 evutil_gettimeofday() 获取当前实际时间。成功时返回 0，失败时返回负数。

请注意，由于 Libevent 开始运行回调函数时会缓存 timeval 值，因此它至少会略有误差。如果您的回调函数运行时间很长，则误差可能非常大。要强制立即更新缓存，您可以调用以下函数：

**Interface**
```c
int event_base_update_cache_time(struct event_base *base);
```

成功时返回 0，失败时返回 -1，如果基地没有运行其事件循环，则不会产生任何效果。

event_base_gettimeofday_cached() 函数是 Libevent 2.0.4-alpha 中的新增函数。Libevent 2.1.1-alpha 添加了 event_base_update_cache_time() 函数。

## 转储 event_base 状态

**Interface**
```c
void event_base_dump_events(struct event_base *base, FILE *f);
```

为了帮助您调试程序（或调试 Libevent！），您有时可能需要获取 event_base 中添加的所有事件及其状态的完整列表。调用 event_base_dump_events() 函数会将此列表写入提供的 stdio 文件。

该列表旨在方便人类阅读；其格式将在 Libevent 的未来版本中发生变化。

此功能是在 Libevent 2.0.1-alpha 版本中引入的。

## 对 event_base 中的每个事件运行一个函数

**Interface**
```c
typedef int (*event_base_foreach_event_cb)(const struct event_base *,
    const struct event *, void *);

int event_base_foreach_event(struct event_base *base,
                             event_base_foreach_event_cb fn,
                             void *arg);
```

您可以使用 `event_base_foreach_event()` 遍历与 `event_base()` 关联的每个当前活动或待处理的事件。提供的回调函数将按任意顺序为每个事件调用一次。`event_base_foreach_event()` 的第三个参数将作为第三个参数传递给每次回调函数的调用。

回调函数必须返回 0 才能继续迭代，或返回其他整数才能停止迭代。回调函数最终返回的值将由 event_base_foreach_function() 返回。

你的回调函数不得修改它接收的任何事件，也不得向事件库添加或删除任何事件，或以其他方式修改与事件库关联的任何事件，否则可能会发生未定义行为，包括崩溃和堆崩溃。

在调用 event_base_foreach_event() 期间，event_base 锁将被持有——这将阻止其他线程对 event_base 进行任何有用的操作，因此请确保您的回调不会花费太长时间。

此功能是在 Libevent 2.1.2-alpha 中添加的。
