# 基础教程 10：GStreamer 工具

## 目标

GStreamer 附带一系列工具，从方便实用到必不可少，应有尽有。本教程不涉及任何代码，您只需放松观看，我们将教您：

- 如何完全不使用 C 语言，通过命令行构建和运行 GStreamer 管道！
- 如何了解您有哪些 GStreamer 元素可用及其功能。
- 如何发现媒体文件的内部结构。

## 介绍

这些工具位于 GStreamer 二进制文件的 bin 目录中。您需要切换到该目录才能执行它们，因为它没有添加到系统PATH环境变量中（以避免对系统造成过多污染）。

只需打开终端（或控制台窗口），然后进入binGStreamer 安装目录（请再次阅读“安装 GStreamer”部分以查找其位置），即可开始输入本教程中给出的命令。

    在 Linux 系统上，您应该使用随发行版一起安装的 GStreamer 版本；gstreamer1 在 Fedora 等发行版上，这些工具应该通过名为 `gstreamer` 的软件包进行安装；而gstreamer1.0-tools在 Debian/Ubuntu 等发行版上，这些工具应该通过名为 `gstreamer` 的软件包进行安装。

为了允许多个 GStreamer 版本在同一系统中共存，这些工具都进行了版本控制，即在其名称后附加 GStreamer 版本号。此版本基于 GStreamer 1.0，因此这些工具的名称分别为 `<gStreamer-1.0>`和 `< gst-launch-1.0gStreamer -1.0>`。gst-inspect-1.0gst-discoverer-1.0

## gst-launch-1.0

此工具接受管道的文本描述，将其实例化并设置为 PLAYING 状态。它允许您在实际使用 GStreamer API 调用实现之前，快速检查给定管道是否正常工作。

请注意，它只能创建简单的管道。特别是，它只能在一定程度上模拟管道与应用程序的交互。无论如何，它对于快速测试管道非常方便，并且被世界各地的 GStreamer 开发人员每天使用。

请注意，它gst-launch-1.0主要是一个面向开发人员的调试工具。您不应该基于它构建应用程序。相反，您应该使用gst_parse_launch()GStreamer API 的功能，以便根据管道描述轻松构建管道。

虽然构建管道描述的规则非常简单，但多个元素的连接很容易让这些描述变得像魔法一样复杂。不过别担心，每个人 gst-launch-1.0最终都会掌握这些语法。

gst-launch-1.0 的命令行由一系列选项和一个管道描述组成。接下来给出一些简化的说明，完整文档请参见 参考页面gst-launch-1.0。

### Elements

简单来说，管道描述 (PIPELINE-DESCRIPTION) 就是一个元素类型列表，元素类型之间用感叹号 (!) 分隔。请尝试输入以下命令：

```shell
gst-launch-1.0 videotestsrc ! videoconvert ! autovideosink
```

你应该会看到一个带有动画视频图案的窗口。在终端中使用 CTRL+C 停止程序。

这会实例化一个新的元素，类型分别为videotestsrc（用于生成示例视频图案的元素）、videoconvert（用于执行原始视频格式转换的元素，确保其他元素可以相互识别）和autovideosink（用于渲染视频的窗口）。然后，GStreamer 会尝试将每个元素的输出链接到其描述中右侧元素的输入。如果有多个输入或输出 Pad 可用，则会使用 Pad Caps 来查找两个兼容的 Pad。

### Properties

可以将属性附加到元素上，格式为 *属性=值*（可以指定多个属性，用空格分隔）。使用工具gst-inspect-1.0（如下所述）可以查找元素的可用属性。

```shell
gst-launch-1.0 videotestsrc pattern=11 ! videoconvert ! autovideosink
```

你应该会看到一个由圆圈组成的静态视频图案。

### Named elements

可以使用属性为元素命名name，这样就可以创建包含分支的复杂管道。名称允许链接到描述中先前创建的元素，并且对于使用具有多个输出端口的元素（例如解复用器或T型管）来说必不可少。

命名元素用其名称后跟一个点来表示。

```shell
gst-launch-1.0 videotestsrc ! videoconvert ! tee name=t ! queue ! autovideosink t. ! queue ! autovideosink
```

你应该看到两个视频窗口，显示相同的示例视频图案。如果你只看到一个窗口，请尝试移动它，因为它可能覆盖了第二个窗口。

此示例实例化了一个 `<T>` videotestsrc，它链接到一个 `<T>` videoconvert，再链接到一个tee`<T>`（回想一下基础教程 7：多线程和填充可用性， `<T> tee` 会将通过其输入填充的所有数据复制到其每个输出填充）。`<T> tee` 被简单地命名为“t”（使用name属性），然后链接到一个 ` <T>` 和一个 `<T> queue` 。autovideosink同一个tee`<T>` 被命名为“t.”（注意点号），然后链接到第二个 `<T>` queue和第二个 `<T>` autovideosink。

要了解为什么需要队列，请阅读基础教程 7：多线程和填充可用性。

### Pads

在连接两个元素时，与其让 GStreamer 自动选择 Pad，您可能更希望直接指定 Pad。您可以通过在元素名称后添加一个点号和 Pad 名称来实现这一点（该元素必须是已命名的元素）。您可以使用该工具来了解元素的 Pad 名称gst-inspect-1.0。

例如，当您想要从解复用器中检索某个特定的数据流时，这非常有用：

```shell
gst-launch-1.0 souphttpsrc location=https://gstreamer.freedesktop.org/data/media/sintel_trailer-480p.webm ! matroskademux name=d d.video_0 ! matroskamux ! filesink location=sintel_video.mkv
```

这段代码使用 GStreamer 从互联网获取一个souphttpsrcwebm 格式的媒体文件（webm 是一种特殊的 Matroska 容器，参见基础教程 2：GStreamer 概念）。然后，我们使用 GStreamer 打开该容器matroskademux。由于该媒体文件包含音频和视频，因此 GStreamermatroskademux会创建两个输出 Pad，分别命名为 `sintel_video.mkv`video_0和`sintel_video.mkv` audio_0。我们链接video_0到一个` matroskamuxsintel_video.mkv` 元素，将视频流重新打包到一个新的容器中，最后将其链接到一个filesink`sintel_video.mkv` 元素，该元素会将视频流写入名为“sintel_video.mkv”的文件（`sintel_video.mkv`location属性指定文件名）。

总而言之，我们获取了一个 webm 文件，去除其中的音频，然后生成了一个包含视频的新 matroska 文件。如果我们只想保留音频：

```shell
gst-launch-1.0 souphttpsrc location=https://gstreamer.freedesktop.org/data/media/sintel_trailer-480p.webm ! matroskademux name=d d.audio_0 ! vorbisparse ! matroskamux ! filesink location=sintel_audio.mka
```

该vorbisparse元素需要从数据流中提取一些信息并将其放入 Pad Caps 中，以便下一个元素 matroskamux知道如何处理该数据流。对于视频而言，这并非必要，因为matroskademux已经提取了这些信息并将其添加到 Caps 中。

请注意，以上两个示例中，没有任何媒体被解码或播放。我们只是将媒体从一个容器转移到了另一个容器（再次进行解复用和重复用）。

### Caps filters

当一个元素有多个输出焊盘时，与下一个元素的连接可能会出现歧义：下一个元素可能拥有多个兼容的输入焊盘，或者它的输入焊盘可能与所有输出焊盘的焊盘特性都兼容。在这种情况下，GStreamer 会使用第一个可用的焊盘进行连接，这实际上相当于 GStreamer 会随机选择一个输出焊盘。

请考虑以下管道：

```shell
gst-launch-1.0 souphttpsrc location=https://gstreamer.freedesktop.org/data/media/sintel_trailer-480p.webm ! matroskademux ! filesink location=test
```

这与上一个例子中的媒体文件和解复用器相同。输入焊盘的引脚配置为filesink，ANY这意味着它可以接受任何类型的媒体。的两个输出焊盘中，哪一个matroskademux会连接到文件接收器？video_0是还是audio_0？你无法确定。

不过，您可以通过使用命名垫（如上一小节所述）或使用大写字母过滤器来消除这种歧义：

```shell
gst-launch-1.0 souphttpsrc location=https://gstreamer.freedesktop.org/data/media/sintel_trailer-480p.webm ! matroskademux ! video/x-vp8 ! matroskamux ! filesink location=sintel_video.mkv
```

Caps Filter 的作用类似于一个直通元素，它不做任何操作，只接受具有给定 Caps 的媒体，从而有效地消除了歧义。在本例中，我们在matroskademux和之间matroskamux添加了一个Caps Filter，以指定我们感兴趣的是能够生成此类视频的video/x-vp8输出垫。matroskademux

要查找元素接受和产生的容量，请使用该 gst-inspect-1.0工具。要查找特定文件中包含的容量，请使用该gst-discoverer-1.0工具。要查找元素为特定管道产生的容量，请gst-launch-1.0照常运行该工具，并 –v选择打印容量信息的选项。

### Examples

使用以下方式播放媒体文件playbin（如基础教程 1：Hello world! 中所示）：

```shell
gst-launch-1.0 playbin uri=https://gstreamer.freedesktop.org/data/media/sintel_trailer-480p.webm
```

playbin一个功能齐全的播放管道，包含音频和视频（与内部生成的管道大致相同）：

```shell
gst-launch-1.0 souphttpsrc location=https://gstreamer.freedesktop.org/data/media/sintel_trailer-480p.webm ! matroskademux name=d ! queue ! vp8dec ! videoconvert ! autovideosink d. ! queue ! vorbisdec ! audioconvert ! audioresample ! autoaudiosink
```

转码流程会打开 webm 容器，解码音频和视频流（通过 uridecodebin），然后使用不同的编解码器（H.264 + AAC）重新编码音频和视频分支，最后将它们重新组合到一个 MP4 容器中（只是为了方便）。由于 x264enc 编码器的默认行为（在输出任何内容之前会消耗数秒的视频输入），我们必须增加音频分支的队列大小，以确保流程可以预加载并启动。另一种解决方案是使用其他方法，x264enc tune=zerolatency但这会导致质量降低，更适合直播场景。

```shell
gst-launch-1.0 uridecodebin uri=https://gstreamer.freedesktop.org/data/media/sintel_trailer-480p.webm name=d ! queue ! videoconvert ! x264enc ! video/x-h264,profile=high ! mp4mux name=m ! filesink location=sintel.mp4 d. ! queue max-size-time=5000000000 max-size-bytes=0 max-size-buffers=0 ! audioconvert ! audioresample ! voaacenc ! m.
```

一个重新缩放管道。videoscale当输入和输出画面尺寸不同时，该元素会执行重新缩放操作。输出画面尺寸由画面过滤器设置为 320x200。

```shell
gst-launch-1.0 uridecodebin uri=https://gstreamer.freedesktop.org/data/media/sintel_trailer-480p.webm ! queue ! videoscale ! video/x-raw,width=320,height=200 ! videoconvert ! autovideosink
```

这段简短的描述gst-launch-1.0应该足以帮助您入门。请记住，您可以在这里找到完整的文档。

## gst-inspect-1.0

- 不带参数时，它会列出所有可用的元素类型，即可用于实例化新元素的类型。
