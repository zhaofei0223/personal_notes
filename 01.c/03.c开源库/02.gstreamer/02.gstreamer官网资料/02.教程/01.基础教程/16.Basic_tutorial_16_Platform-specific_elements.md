# 基础教程 16：平台特定元素

## 目标

尽管 GStreamer 是一个跨平台框架，但并非所有元素都适用于所有平台。例如，视频接收器严重依赖于底层窗口系统，因此需要根据平台选择不同的窗口系统。通常情况下，使用 `<video>`playbin或 ` <video>` 等元素时无需担心这个问题autovideosink，但如果您需要使用仅在特定平台上可用的接收器，本教程将为您介绍它们的一些特性。

## 跨平台

**glimagesink**

此视频接收器基于 OpenGL或OpenGL ES。它支持缩放和图像滤波，以减轻锯齿。它实现了 VideoOverlay 接口，因此视频窗口可以重新父级化（嵌入到其他窗口内）。除 Windows 平台外，大多数平台都推荐使用此视频接收器（在 Windows 平台上，d3d11videosink推荐使用其他视频接收器）。尤其是在 Android 和 iOS 平台上，它是唯一可用的视频接收器。它可以被分解， glupload ! glcolorconvert ! glimagesinkelement以便在流水线中插入更多 OpenGL 硬件加速处理。

## Linux

**ximagesink**

这是一个标准的基于 X 的 RGB 视频接收器。它实现了 VideoOverlay 接口，因此视频窗口可以被重新指定父窗口（嵌入到其他窗口内）。它不支持缩放或 RGB 以外的颜色格式；这些功能必须通过其他方式实现（ videoscale例如使用 `<video>` 元素）。

**xvimagesink**

这是一个基于 X 的视频接收器，使用X 视频扩展(Xv)。它实现了 VideoOverlay 接口，因此视频窗口可以被重新指定父窗口（嵌入到其他窗口内）。它能够高效地在 GPU 上进行缩放。仅当硬件和相应的驱动程序支持 Xv 扩展时，它才可用。

**alsasink**

该音频接收器通过ALSA （高级 Linux 音频架构）将音频输出到声卡 。几乎所有 Linux 平台都支持此接收器。它通常被视为声卡的“底层”接口，配置起来可能比较复杂（参见播放教程 9：数字音频直通的评论 ）。

**pulsesink**

这个音频接收器会将音频输出到PulseAudio 服务器。它比 ALSA 更高级地抽象了声卡，因此更易于使用并提供更多高级功能。不过，它在某些较旧的 Linux 发行版上稳定性较差。

## Mac OS X

**osxvideosink**

这是Mac OS X系统上GStreamer可用的视频接收器。也可以使用glimagesinkOpenGL进行绘图。

**osxaudiosink**

这是 GStreamer 在 Mac OS X 上唯一可用的音频接收器。

## 视窗

**d3d11videosink**

这款视频接收器基于Direct3D11 ，是 Windows 系统上的推荐组件。它支持 VideoOverlay 接口，并能以零拷贝方式进行缩放/色彩空间转换。它是 Windows 系统上性能最高、功能最全面的视频接收器组件。

**d3dvideosink**

此视频接收器基于 Direct3D9。它支持缩放和过滤缩放后的图像以减轻锯齿。它实现了 VideoOverlay 接口，因此视频窗口可以重新设置父级（嵌入到其他窗口内）。不建议在面向 Windows 8 或更高版本的应用程序中使用此组件。

**dshowvideosink (deprecated)**

此视频接收器基于DirectShow。它可以使用不同的渲染后端，例如 EVR、 VMR9 或 VMR7，其中 EVR 仅适用于 Windows Vista 或更高版本。它支持缩放和过滤缩放后的图像以减轻锯齿。它实现了 VideoOverlay 接口，因此视频窗口可以重新指定父窗口（嵌入到其他窗口内）。在大多数情况下，不建议使用此组件。

**wasapisink和wasapi2sink**

这些元素是 Windows 上的默认音频接收器元素，基于 WASAPI，该 API 在 Vista 或更高版本中可用。请注意，它wasapi2sink是 `<audio-sink>` 的替代品wasapisink，并且wasapi2sink是 Windows 8 或更高版本的默认音频接收器元素。否则，wasapisink`<audio-sink>` 将是默认音频接收器元素。

**directsoundsink (deprecated)**

该音频接收器元件基于 DirectSound，所有 Windows 版本均提供此功能。

**dshowdecwrapper**

Direct Show是一个类似于 GStreamer 的多媒体框架。不过，它们之间存在足够的差异，因此它们的管道无法直接互连。但是，通过这个组件，GStreamer 可以利用 Direct Show 中已有的解码组件。该dshowdecwrapper组件封装了多个 Direct Show 解码器，使其可以嵌入到 GStreamer 管道中。使用该gst-inspect-1.0工具（参见基础教程 10：GStreamer 工具）可以查看可用的解码器。

## 安卓

**openslessink**

这是安卓系统上GStreamer唯一可用的音频接收器。它基于OpenSL ES。

**openslessrc**

这是安卓系统上GStreamer唯一可用的音频源。它基于OpenSL ES。

**androidmedia**

android.media.MediaCodec 是 Android 特有的 API，用于访问设备上可用的编解码器，包括硬件编解码器。它从 API 级别 16（JellyBean）开始可用，GStreamer 可以通过 androidmedia 插件使用它进行音频和视频解码。在 Android 上，将硬件解码器附加到 `<head>`glimagesink元素可以构建高性能的零拷贝 decodebin 流水线。

**ahcsrc**

该视频源可以从 Android 设备上的摄像头捕获视频，它是 androidmedia 插件的一部分，并使用android.hardware.Camera API。

## iOS

**osxaudiosink**

这是iOS上GStreamer唯一可用的音频接收器。

**iosassetsrc**

playbin用于读取 iOS 资源的源元素，即存储在资源库中的文档（例如照片、音乐和视频）。当 URI 使用 特定方案时，它可以自动实例化assets-library://。

**iosavassetsrc**

用于读取和解码 iOS 音视频资源（即存储在资源库中的文档，例如照片、音乐和视频）的源元素。playbin当 URI 使用 ipod-library://特定方案时，它可以自动实例化。解码由系统执行，因此如果可用，将使用专用硬件。

## 结论

本教程介绍了一些 GStreamer 元素的具体细节，这些元素并非在所有平台上都可用。如果您使用跨平台元素（例如 `<GStreamer>`playbin或 `<GStreamer>` ），则无需担心这些细节autovideosink；但如果您需要手动实例化这些元素，了解它们的特性会很有帮助。
