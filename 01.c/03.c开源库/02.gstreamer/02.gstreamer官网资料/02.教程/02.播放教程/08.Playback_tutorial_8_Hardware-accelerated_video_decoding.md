# 播放教程 8：硬件加速视频解码

## 目标

随着低功耗设备的日益普及，硬件加速视频解码已迅速成为一种必需技术。本教程（实际上更像是一堂讲座）将介绍硬件加速的一些背景知识，并解释 GStreamer 如何从中受益。

抢先看：如果设置正确，您无需进行任何特殊操作即可激活硬件加速；GStreamer 会自动利用它。

## 介绍

视频解码是一项极其消耗 CPU 资源的任务，尤其是在处理 1080p 高清电视等高分辨率视频时。幸运的是，配备可编程 GPU 的现代显卡能够承担这项工作，使 CPU 可以专注于其他任务。对于低功耗 CPU 而言，由于其解码速度不足，专用硬件就显得至关重要。

截至目前（2016 年 6 月），每个 GPU 制造商都提供不同的硬件访问方法（不同的 API），尚未形成强有力的行业标准。

截至2016年6月，至少存在8种不同的视频解码加速API：

- VAAPI（视频加速 API）：最初由 英特尔于 2007 年设计，面向基于 Unix 操作系统的 X Window 系统，现已开源。它现在也通过 dmabuf 支持 Wayland。目前，它不再局限于英特尔 GPU，其他厂商也可以自由使用此 API，例如 Imagination Technologies或 S3 Graphics。GStreamerva可以通过插件访问它gst-plugins-bad。

- OVD （Open Video Decode ）： AMD Graphics提供的另一个 API ，旨在为软件开发人员提供一种平台无关的方法，以利用 AMD Radeon 显卡内部的通用视频解码(UVD) 硬件。目前 GStreamer 尚不支持此 API。

- DCE （分布式编解码器引擎）：德州仪器公司开发的开源软件库（“libdce”）和 API 规范，面向 Linux 系统和 ARM 平台。可通过gstreamer-ducati插件供 GStreamer 访问。

- Android MediaCodec：这是 Android 提供的 API，用于访问设备的硬件解码器和编码器（如果可用）。可通过 androidmediagst-plugins-bad 插件访问。它包含编码和解码功能。

- Apple VideoTool Box 框架：Apple 的 API 可通过applemedia插件访问硬件，包括通过vtenc元素进行编码和通过vtdec元素进行解码。

- Video4Linux：最新的 Linux 内核提供了一个内核 API，可以以标准方式公开硬件编解码器，该 v4l2插件现在支持此功能gst-plugins-good。根据平台的不同，它可以同时支持解码和编码。

## 硬件加速视频解码插件的内部工作原理

这些 API 通常提供多种功能，例如视频解码、后处理或​​解码帧的呈现。相应地，插件通常为每种功能提供不同的 GStreamer 元素，因此可以构建满足任何需求的管道。

例如，该va插件gst-plugins-bad提供了 vah264dec、vah264dec、vahav1dec等元素，vapostproc分别允许通过 VAAPI 进行硬件加速解码、将原始视频帧上传到 GPU 内存、将 GPU 帧下载到系统内存以及呈现 GPU 帧。

区分驻留在系统内存中的传统 GStreamer 帧和由硬件加速 API 生成的帧非常重要。后者驻留在 GPU 内存中，GStreamer 无法直接操作。虽然在映射时通常可以将它们下载到系统内存并像传统 GStreamer 帧一样处理，但将它们留在 GPU 中并从 GPU 显示效率更高。

不过，GStreamer 需要跟踪这些“硬件缓冲区”的位置，因此传统的缓冲区仍然会在元素之间传递。它们看起来像普通的缓冲区，但由于必须从硬件加速元素使用的特殊内存中检索内容，因此映射其内容的速度要慢得多。这些特殊内存类型是通过分配查询机制协商确定的。

这意味着，如果系统中存在特定的硬件加速 API，并且相应的 GStreamer 插件也可用，那么诸如 `GStreamer` 之类的自动插入元素playbin3就可以自由地使用硬件加速来构建其管道；应用程序无需执行任何特殊操作即可启用它。几乎如此：

当playbin3需要在多个同样有效的选项中进行选择时，例如传统的软件解码（vp8dec例如通过 `std::string`）或硬件加速解码（例如通过`std::string`），程序会根据选项的优先级vavp8dec（例如排名）来做决定。优先级是每个选项的属性，表示其优先级；程序会选择能够构建完整流水线且优先级最高的选项。playbin3

因此，是否playbin3启用硬件加速取决于所有能够处理该媒体类型的元素的相对排名。所以，确保启用或禁用硬件加速的最简单方法是通过环境变量更改相关元素的排名GST_PLUGIN_FEATURE_RANK（更多信息请参阅文档中的“运行和调试 GStreamer 应用程序”）。另一种方法是在应用程序中设置排名，如下面的代码所示：

```c
static void enable_factory (const gchar *name, gboolean enable) {
    GstRegistry *registry = NULL;
    GstElementFactory *factory = NULL;

    registry = gst_registry_get_default ();
    if (!registry) return;

    factory = gst_element_factory_find (name);
    if (!factory) return;

    if (enable) {
        gst_plugin_feature_set_rank (GST_PLUGIN_FEATURE (factory), GST_RANK_PRIMARY + 1);
    }
    else {
        gst_plugin_feature_set_rank (GST_PLUGIN_FEATURE (factory), GST_RANK_NONE);
    }

    gst_registry_add_feature (registry, GST_PLUGIN_FEATURE (factory));
    return;
}
```

传递给此方法的第一个参数是要修改的元素的名称，例如vavp9dec或fluvadec。

关键方法是gst_plugin_feature_set_rank()设置请求元素工厂的等级，使其达到所需级别。为方便起见，等级分为 NONE、MARGINAL、SECONDARY 和 PRIMARY 四个级别，但也可以设置任意数字。启用元素时，我们将其等级设置为 PRIMARY+1，使其高于其他通常为 PRIMARY 级别的元素。将元素的等级设置为 NONE 将使自动插拔机制永远不会选择它。

    GStreamer开发者通常会降低存在缺陷的硬件解码器的排名，使其低于软件解码器。这应该引起重视。

## 结论

本教程简要展示了 GStreamer 内部如何管理硬件加速视频解码。具体来说，

- 如果提供了合适的 API 和相应的 GStreamer 插件，应用程序无需进行任何特殊操作即可启用硬件加速。
- 可以通过环境变量更改解码元素的 rank 来启用或禁用硬件加速，或者在代码中GST_PLUGIN_FEATURE_RANK 使用。gst_plugin_feature_set_rank()
