# Position tracking and seeking

到目前为止，我们已经了解了如何创建媒体处理管道以及如何运行它。大多数应用程序开发人员都希望向用户提供媒体处理进度的反馈。例如，媒体播放器会显示一个滑块来指示歌曲的播放进度，通常还会显示一个标签来指示流的长度。转码应用程序会显示一个进度条，指示任务已完成的百分比。GStreamer 内置了对所有这些操作的支持，它使用了一种称为查询的概念。由于查找操作与之非常相似，因此这里也会讨论查找操作。查找操作是使用事件的概念来实现的。

## Querying: getting the position or length of a stream

查询是指请求与进度跟踪相关的特定流属性。这包括获取流的长度（如果可用）或获取当前位置。这些流属性可以以多种格式检索，例如时间、音频样本、视频帧或字节。最常用的查询函数是 `query()` gst_element_query ()，尽管也提供了一些便捷的包装函数（例如`query()`gst_element_query_position ()和 ` gst_element_query_duration ()query()`）。通常，您可以直接查询管道，它会自动处理内部细节，例如要查询哪个元素。

在内部，查询会被发送到各个接收器，并向后“分发”，直到某个元素能够处理它；处理结果会被发送回函数调用者。通常情况下，调用者是解复用器，但对于实时源（例如来自网络摄像头的源），调用者则是源本身。

```c

#include <gst/gst.h>

static gboolean
cb_print_position (GstElement *pipeline)
{
  gint64 pos, len;

  if (gst_element_query_position (pipeline, GST_FORMAT_TIME, &pos)
    && gst_element_query_duration (pipeline, GST_FORMAT_TIME, &len)) {
    g_print ("Time: %" GST_TIME_FORMAT " / %" GST_TIME_FORMAT "\r",
         GST_TIME_ARGS (pos), GST_TIME_ARGS (len));
  }

  /* call me again */
  return TRUE;
}

gint
main (gint   argc,
      gchar *argv[])
{

[..]

  /* run pipeline */
  g_timeout_add (200, (GSourceFunc) cb_print_position, pipeline);
```

## Events: seeking (and more)

事件的工作方式与查询非常相似。例如，事件的分发方式与查询完全相同（也存在相同的限制），它们同样可以发送到顶层管道，管道会自动处理所有事情。虽然应用程序和元素可以通过更多方式使用事件进行交互，但这里我们只关注查找操作。查找操作通过查找事件来实现。查找事件包含播放速率、查找偏移格式（即要跟踪的偏移单位，例如时间、音频样本、视频帧或字节）、可选的一组查找相关标志（例如是否应刷新内部缓冲区）、查找方法（指示相对于给定偏移量的位置）以及查找偏移量。

第一个偏移量（start）是要跳转到的新位置，而第二个偏移量（stop）是可选的，用于指定流式传输停止的位置。通常情况下，只需将第一个偏移量指定GST_SEEK_TYPE_NONE 为第一个偏移量，stop_type第二个偏移量指定GST_CLOCK_TIME_NONE为第二stop个偏移量即可。

查找操作的行为也包含在gst_element_seek()`and` 函数中gst_element_seek_simple()，通常情况下，你会使用这些函数来启动管道上的查找操作。

```c
static void
seek_to_time (GstElement *pipeline,
          gint64      time_nanoseconds)
{
  if (!gst_element_seek (pipeline, 1.0, GST_FORMAT_TIME, GST_SEEK_FLAG_FLUSH,
                         GST_SEEK_TYPE_SET, time_nanoseconds,
                         GST_SEEK_TYPE_NONE, GST_CLOCK_TIME_NONE)) {
    g_print ("Seek failed!\n");
  }
}
```

使用 GST_SEEK_FLAG_FLUSH 进行寻道操作时，管道应处于 PAUSED 或 PLAYING 状态。寻道操作后，管道将自动进入预滚动状态，直到寻道操作后的新数据再次触发管道预滚动。管道预滚动完成后，将恢复到执行寻道操作时的状态（PAUSED 或 PLAYING）。您可以等待（阻塞）寻道操作完成， gst_element_get_state()或者等待总线上出现 ASYNC_DONE 消息。

仅当管道处于 PLAYING 状态时，才应执行不带 GST_SEEK_FLAG_FLUSH 标志的查找操作。在 PAUSED 状态下执行非刷新查找操作可能会导致死锁，因为管道流线程可能被阻塞在接收器上。

需要注意的是，查找操作并非在函数返回时立即完成gst_element_seek () 。根据具体情况，实际的查找操作可能会在另一个线程（流式线程）中稍后执行，并且从新的查找位置到下游元素（例如接收器）可能需要一些时间（如果查找操作是非刷新式的，则可能需要更长时间）。

可以在短时间内进行多次寻址，例如直接响应滑块移动。寻址完成后，管道内部会暂停（如果正在播放），位置会在内部重置，解复用器和解码器将从新位置开始解码，如此循环往复，直到所有输出端都重新获得数据。如果原本正在播放，也会重新开始播放。由于新位置会立即显示在视频输出中，即使管道未处于播放状态，您也能看到新的帧。
