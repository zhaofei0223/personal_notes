# Interfaces

将元素用作 GObject可以让GObject 应用程序和元素之间通过属性进行交互变得简单。这种方法适用于简单的 getter 和 setter 方法，但对于更复杂的情况则不适用。对于更复杂的用例，GStreamer 会使用基于类型的接口 GObject GTypeInterface 。

本文旨在提供入门介绍，不包含源代码示例。更多详情请参阅 API 参考文档。

## The URI Handler interface

到目前为止，我们的示例中只展示了使用“filesrc”元素对本地文件的支持，但 GStreamer 支持更多位置源。

GStreamer 不需要应用程序了解任何URI具体细节，例如针对特定网络源类型应该使用哪个元素。这些细节都由GstURIHandler接口抽象化了。

命名没有严格的规则URI，但通常我们遵循常用的命名约定。例如，假设您已安装正确的插件，GStreamer 支持：

```json5
file:///<path>/<file>
http://<host>/<path>/<file>
rtsp://<host>/<path>
dvb://<CHANNEL>
...
```

要获取支持特定 URI 的源元素或目标元素，请根据所需方向使用gst_element_make_from_uri ()withGST_URI_SRC或GST_URI_SINK as 。GstURIType

您可以使用 GLib 的 和 将文件名转换为 URI， g_filename_to_uri ()反之亦然g_uri_to_filename ()。

## The Color Balance interface

该GstColorBalance接口用于控制元素上的视频相关属性，例如亮度、对比度等。它存在的唯一原因是，据其作者所知，目前还没有办法使用动态注册属性GObject。

colorbalance 接口由多个插件实现，包括 xvimagesink和glimagesink元素Video4linux2。

## The Video Overlay interface

该GstVideoOverlay接口旨在解决在应用程序窗口中嵌入视频流的问题。应用程序会向实现此接口的元素提供一个窗口句柄，该元素随后会使用此窗口句柄进行绘制，而无需创建新的顶级窗口。这对于在视频播放器中嵌入视频非常有用。

该接口由Video4linux2 元素和glimagesink、、ximagesink和xvimagesink等实现sdlvideosink。

## Other interfaces

GStreamer 还提供了许多其他接口，并且其某些组件也实现了这些接口。其中包括：

- GstChildProxy要访问多子元素的内部元素属性
- GstNavigation用于发送和解析导航事件
- GstPreset用于处理元素预设
- GstRTSPExtensionRTSP 扩展接口
- GstStreamVolume用于提供访问和控制流音量级别的接口
- GstTagSetter用于处理媒体元数据
- GstTagXmpWriter对于提供 XMP 序列化的元素
- GstTocSetter用于设置和检索类似TOC的数据
- GstTuner用于提供射频调谐操作的元件
- GstVideoDirection用于视频旋转和翻转控制
- GstVideoOrientation视频方向控制
- GstWaylandVideoWayland视频接口
