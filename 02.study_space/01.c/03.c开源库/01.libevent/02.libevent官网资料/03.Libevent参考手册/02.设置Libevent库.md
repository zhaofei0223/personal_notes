Libevent有一些全局设置，这些设置在整个流程中共享，并影响整个库。

在调用 Libevent 库的任何其他部分之前，必须先对这些设置进行更改。否则，Libevent 可能会处于不一致的状态。

## Libevent 中的日志消息

Libevent 可以记录内部错误和警告。如果编译时启用了日志记录支持，它还会记录调试信息。默认情况下，这些信息会写入标准错误输出 (stderr)。您可以通过提供自定义日志记录函数来覆盖此默认行为。

**Interface**
```c
#define EVENT_LOG_DEBUG 0
#define EVENT_LOG_MSG   1
#define EVENT_LOG_WARN  2
#define EVENT_LOG_ERR   3

/* Deprecated; see note at the end of this section */
#define _EVENT_LOG_DEBUG EVENT_LOG_DEBUG
#define _EVENT_LOG_MSG   EVENT_LOG_MSG
#define _EVENT_LOG_WARN  EVENT_LOG_WARN
#define _EVENT_LOG_ERR   EVENT_LOG_ERR

typedef void (*event_log_cb)(int severity, const char *msg);

void event_set_log_callback(event_log_cb cb);
```

要覆盖 Libevent 的日志记录行为，请编写一个与 event_log_cb 签名匹配的自定义函数，并将其作为参数传递给 event_set_log_callback() 函数。每当 Libevent 需要记录消息时，它都会将消息传递给您提供的函数。您可以通过再次调用 event_set_log_callback() 函数并传入 NULL 作为参数，使 Libevent 恢复其默认行为。

**Examples**
```c
#include <event2/event.h>
#include <stdio.h>

static void discard_cb(int severity, const char *msg)
{
    /* This callback does nothing. */
}

static FILE *logfile = NULL;
static void write_to_file_cb(int severity, const char *msg)
{
    const char *s;
    if (!logfile)
        return;
    switch (severity) {
        case _EVENT_LOG_DEBUG: s = "debug"; break;
        case _EVENT_LOG_MSG:   s = "msg";   break;
        case _EVENT_LOG_WARN:  s = "warn";  break;
        case _EVENT_LOG_ERR:   s = "error"; break;
        default:               s = "?";     break; /* never reached */
    }
    fprintf(logfile, "[%s] %s\n", s, msg);
}

/* Turn off all logging from Libevent. */
void suppress_logging(void)
{
    event_set_log_callback(discard_cb);
}

/* Redirect all Libevent log messages to the C stdio file 'f'. */
void set_logfile(FILE *f)
{
    logfile = f;
    event_set_log_callback(write_to_file_cb);
}
```

**NOTE**

在用户提供的 event_log_cb 回调函数中调用 Libevent 函数是不安全的！例如，如果您尝试编写一个使用 bufferevents 向网络套接字发送警告消息的日志回调函数，则很可能会遇到一些奇怪且难以诊断的错误。Libevent 的未来版本可能会对某些函数解除此限制。

通常情况下，调试日志未启用，也不会发送到日志回调函数。如果 Libevent 支持调试日志，您可以手动启用它们。

**Interface**

```c
#define EVENT_DBG_NONE 0
#define EVENT_DBG_ALL 0xffffffffu

void event_enable_debug_logging(ev_uint32_t which);
```

调试日志信息繁多，在大多数情况下并不一定有用。调用 `event_enable_debug_logging()` 并指定 `EVENT_DBG_NONE` 参数会启用默认行为；而指定 `EVENT_DBG_ALL` 参数则会启用所有支持的调试日志。未来版本可能会支持更细粒度的选项。

这些函数在 <event2/event.h> 中声明。它们最早出现在 Libevent 1.0c 中，但 event_enable_debug_logging() 函数最早出现在 Libevent 2.1.1-alpha 中。

**兼容性说明**

在 Libevent 2.0.19 稳定版之前，EVENT_LOG_* 宏的名称以下划线开头：_EVENT_LOG_DEBUG、_EVENT_LOG_MSG、_EVENT_LOG_WARN 和 _EVENT_LOG_ERR。这些旧名称已被弃用，仅用于向后兼容 Libevent 2.0.18 稳定版及更早版本。它们可能会在 Libevent 的未来版本中被移除。

## 处理致命错误

当 Libevent 检测到不可恢复的内部错误（例如数据结构损坏）时，其默认行为是调用 exit() 或 abort() 函数退出当前运行的进程。这些错误几乎总是意味着某个地方存在 bug：要么是你的代码有问题，要么是 Libevent 本身存在问题。

如果您希望应用程序更优雅地处理致命错误，可以通过提供一个 Libevent 应该调用的函数来覆盖 Libevent 的行为，而不是退出。

**Interface**
```c
typedef void (*event_fatal_cb)(int err);
void event_set_fatal_callback(event_fatal_cb cb);
```

要使用这些函数，首先需要定义一个新函数，Libevent 在遇到致命错误时应该调用该函数，然后将其传递给 event_set_fatal_callback() 函数。之后，如果 Libevent 遇到致命错误，它将调用您提供的函数。

你的函数不应该将控制权返回给 Libevent；这样做可能会导致未定义行为，而且 Libevent 也可能为了避免崩溃而退出。你的函数一旦被调用，就不应该再调用任何其他 Libevent 函数。

这些函数在 <event2/event.h> 中声明。它们首次出现在 Libevent 2.0.3-alpha 版本中。

## 内存管理

默认情况下，Libevent 使用 C 库的内存管理函数从堆中分配内存。您可以通过提供自定义的 malloc、realloc 和 free 函数，让 Libevent 使用其他内存管理器。如果您希望 Libevent 使用更高效的分配器，或者希望 Libevent 使用经过检测的分配器来查找内存泄漏，则可能需要这样做。

**Interface**
```c
void event_set_mem_functions(void *(*malloc_fn)(size_t sz),
                             void *(*realloc_fn)(void *ptr, size_t sz),
                             void (*free_fn)(void *ptr));
```

这里有一个简单的例子，它将 Libevent 的内存分配函数替换为能够统计已分配字节总数的变体。实际上，当 Libevent 在多线程中运行时，您可能需要在此处添加锁机制以防止错误。

**Example**
```c
#include <event2/event.h>
#include <sys/types.h>
#include <stdlib.h>

/* This union's purpose is to be as big as the largest of all the
 * types it contains. */
union alignment {
    size_t sz;
    void *ptr;
    double dbl;
};
/* We need to make sure that everything we return is on the right
   alignment to hold anything, including a double. */
#define ALIGNMENT sizeof(union alignment)

/* We need to do this cast-to-char* trick on our pointers to adjust
   them; doing arithmetic on a void* is not standard. */
#define OUTPTR(ptr) (((char*)ptr)+ALIGNMENT)
#define INPTR(ptr) (((char*)ptr)-ALIGNMENT)

static size_t total_allocated = 0;
static void *replacement_malloc(size_t sz)
{
    void *chunk = malloc(sz + ALIGNMENT);
    if (!chunk) return chunk;
    total_allocated += sz;
    *(size_t*)chunk = sz;
    return OUTPTR(chunk);
}
static void *replacement_realloc(void *ptr, size_t sz)
{
    size_t old_size = 0;
    if (ptr) {
        ptr = INPTR(ptr);
        old_size = *(size_t*)ptr;
    }
    ptr = realloc(ptr, sz + ALIGNMENT);
    if (!ptr)
        return NULL;
    *(size_t*)ptr = sz;
    total_allocated = total_allocated - old_size + sz;
    return OUTPTR(ptr);
}
static void replacement_free(void *ptr)
{
    ptr = INPTR(ptr);
    total_allocated -= *(size_t*)ptr;
    free(ptr);
}
void start_counting_bytes(void)
{
    event_set_mem_functions(replacement_malloc,
                            replacement_realloc,
                            replacement_free);
}
```

**笔记**

- 替换内存管理函数会影响 Libevent 之后所有分配、调整大小或释放内存的调用。因此，您需要确保在调用任何其他 Libevent 函数之前替换这些函数。否则，Libevent 将使用您编写的 free 函数来释放 C 库 malloc 函数返回的内存。

- 你的 malloc 和 realloc 函数需要返回与 C 库中相同对齐方式的内存块。

- 你的 realloc 函数需要正确处理 realloc(NULL, sz)（即，将其视为 malloc(sz)）。

- 你的 realloc 函数需要正确处理 realloc(ptr, 0)（即，将其视为 free(ptr)）。

- 你的 free 函数不需要处理 free(NULL)。

- 你的 malloc 函数不需要处理 malloc(0)。

- 如果从多个线程中使用 Libevent，则替换的内存管理函数必须是线程安全的。

- Libevent 会使用这些函数来分配内存并将其返回给您。因此，如果您想要释放由 Libevent 函数分配并返回的内存，并且您已经替换了 malloc 和 realloc 函数，那么您可能需要使用您替换的 free 函数来释放它。

event_set_mem_functions() 函数在 <event2/event.h> 中声明。它首次出现在 Libevent 2.0.1-alpha 中。

Libevent 可以禁用 event_set_mem_functions() 函数进行编译。如果禁用，则使用 event_set_mem_functions() 函数的程序将无法编译或链接。在 Libevent 2.0.2-alpha 及更高版本中，您可以通过检查是否定义了 EVENT_SET_MEM_FUNCTIONS_IMPLEMENTED 宏来检测 event_set_mem_functions() 函数是否存在。

## Locks and threading

如果您正在编写多线程程序，您可能知道，同时从多个线程访问相同的数据并不总是安全的。

Libevent 结构体通常可以通过三种方式与多线程配合使用。

- 有些结构本质上是单线程的：同时从多个线程使用它们是不安全的。

- 有些结构体是可选锁定的：您可以告诉 Libevent 每个对象是否需要同时从多个线程使用它。

- 有些结构始终处于锁定状态：如果 Libevent 运行支持锁，则始终可以安全地从多个线程同时使用它们。

要在 Libevent 中使用锁，您必须告诉 Libevent 要使用哪些锁函数。您需要在调用任何分配需要在线程间共享的结构体的 Libevent 函数之前执行此操作。

如果您正在使用 pthreads 库或 Windows 原生线程代码，那就太好了。Libevent 中预定义了一些函数，可以自动配置 Libevent 使用正确的 pthreads 或 Windows 函数。

**Interface**
```c
#ifdef WIN32
int evthread_use_windows_threads(void);
#define EVTHREAD_USE_WINDOWS_THREADS_IMPLEMENTED
#endif
#ifdef _EVENT_HAVE_PTHREADS
int evthread_use_pthreads(void);
#define EVTHREAD_USE_PTHREADS_IMPLEMENTED
#endif
```

这两个函数成功时都返回 0，失败时返回 -1。

如果需要使用不同的线程库，那么你需要做更多的工作。你需要定义使用该库来实现以下功能的函数：

- 锁
- 锁定
- 解锁
- 锁分配
- 锁具破坏
- 状况
- 创建条件变量
- 条件变量破坏
- 等待条件变量
- 向条件变量发出信号/广播
- 线程
- 线程 ID 检测

然后，您可以使用 evthread_set_lock_callbacks 和 evthread_set_id_callback 接口将这些功能告知 Libevent。

**Interface**
```c
#define EVTHREAD_WRITE  0x04
#define EVTHREAD_READ   0x08
#define EVTHREAD_TRY    0x10

#define EVTHREAD_LOCKTYPE_RECURSIVE 1
#define EVTHREAD_LOCKTYPE_READWRITE 2

#define EVTHREAD_LOCK_API_VERSION 1

struct evthread_lock_callbacks {
       int lock_api_version;
       unsigned supported_locktypes;
       void *(*alloc)(unsigned locktype);
       void (*free)(void *lock, unsigned locktype);
       int (*lock)(unsigned mode, void *lock);
       int (*unlock)(unsigned mode, void *lock);
};

int evthread_set_lock_callbacks(const struct evthread_lock_callbacks *);

void evthread_set_id_callback(unsigned long (*id_fn)(void));

struct evthread_condition_callbacks {
        int condition_api_version;
        void *(*alloc_condition)(unsigned condtype);
        void (*free_condition)(void *cond);
        int (*signal_condition)(void *cond, int broadcast);
        int (*wait_condition)(void *cond, void *lock,
            const struct timeval *timeout);
};

int evthread_set_condition_callbacks(
        const struct evthread_condition_callbacks *);
```

evthread_lock_callbacks 结构体描述了您的锁定回调及其功能。对于上述版本，lock_api_version 字段必须设置为 EVTHREAD_LOCK_API_VERSION。supported_locktypes 字段必须设置为 EVTHREAD_LOCKTYPE_* 常量的位掩码，以描述您可以支持的锁类型。（从 2.0.4-alpha 版本开始，EVTHREAD_LOCK_RECURSIVE 为必填项，EVTHREAD_LOCK_READWRITE 未使用。）alloc函数必须返回指定类型的新锁。free 函数必须释放指定类型锁所持有的所有资源。lock函数必须尝试以指定模式获取锁，成功返回 0，失败返回非零值。unlock 函数必须尝试解锁锁，成功返回 0，失败返回非零值。

### 认可的锁具类型有：

0

&nbsp;&nbsp;&nbsp;&nbsp;普通的锁，不一定是递归锁。

EVTHREAD_LOCKTYPE_RECURSIVE

&nbsp;&nbsp;&nbsp;&nbsp;这种锁不会阻止已持有它的线程再次请求该锁。其他线程可以在持有该锁的线程解锁该锁的次数达到其最初锁定的次数后，再获取该锁。

EVTHREAD_LOCKTYPE_READWRITE

&nbsp;&nbsp;&nbsp;&nbsp;这种锁允许多个线程同时持有以进行读取操作，但一次只能有一个线程持有以进行写入操作。写入操作会排除所有读取操作。

### 已知的锁定模式有：

EVTHREAD 读取

&nbsp;&nbsp;&nbsp;&nbsp;仅适用于 READWRITE 锁：获取或释放用于读取的锁。

EVTHREAD_WRITE

&nbsp;&nbsp;&nbsp;&nbsp;仅适用于 READWRITE 锁：获取或释放写入锁。

EVTHREAD_TRY

&nbsp;&nbsp;&nbsp;&nbsp;仅用于锁定：仅当可以立即获取锁时才获取锁。

id_fn 参数必须是一个返回 unsigned long 类型的函数，该类型用于标识调用该函数的线程。对于同一个线程，它必须始终返回相同的数字；如果两个不同的线程同时执行，则它们绝不能返回相同的数字。

evthread_condition_callbacks 结构体描述了与条件变量相关的回调函数。对于上述版本，condition_api_version 字段必须设置为 EVTHREAD_CONDITION_API_VERSION。alloc_condition 函数必须返回指向新条件变量的指针。它接收 0 作为参数。free_condition 函数必须释放条件变量占用的存储空间和资源。wait_condition 函数接受三个参数：alloc_condition 分配的条件变量、您提供的 evthread_lock_callbacks.alloc 函数分配的锁，以及可选的超时时间。每次调用该函数时，都会持有该锁；该函数必须释放锁，并等待条件被触发或（可选的）超时时间过去。wait_condition 函数在发生错误时应返回 -1，在条件被触发时返回 0，在超时时返回 1。在返回之前，它应该确保再次持有该锁。最后，`signal_condition` 函数应该唤醒一个正在等待该条件的线程（如果其广播参数为 false），并唤醒所有当前正在等待该条件的线程（如果其广播参数为 true）。该函数仅在持有与该条件关联的锁时才会执行。

有关条件变量的更多信息，请参阅 pthreads 的 pthread_cond_* 函数或 Windows 的 CONDITION_VARIABLE 函数的文档。

**示例**

```c
For an example of how to use these functions, see evthread_pthread.c and
evthread_win32.c in the Libevent source distribution.
```

本节中的函数声明于 `<event2/thread.h>` 头文件中。其中大部分函数最早出现在 Libevent 2.0.4-alpha 版本中。Libevent 2.0.1-alpha 到 2.0.3-alpha 版本使用较旧的接口来设置锁定函数。`event_use_pthreads()` 函数要求您的程序链接到 `event_pthreads` 库。

条件变量函数是 Libevent 2.0.7-rc 中的新增功能；添加这些功能是为了解决一些其他情况下难以解决的死锁问题。

Libevent 可以禁用锁定支持进行构建。如果禁用锁定支持，则使用上述线程相关函数构建的程序将无法运行。

## 调试锁的使用情况

为了帮助调试锁的使用情况，Libevent 提供了一个可选的“锁调试”功能，该功能会对其锁调用进行封装，以便捕获典型的锁错误，包括：

- 打开一把我们实际上并不拥有的锁。
- 重新锁定非递归锁

如果发生这些锁定错误之一，Libevent 将以断言失败退出。

**Interface**
```c
void evthread_enable_lock_debugging(void);
#define evthread_enable_lock_debuging() evthread_enable_lock_debugging()
```

**笔记**

> 必须在创建或使用任何锁之前调用此函数。为确保安全，请在设置线程函数之后立即调用它。

该函数在 Libevent 2.0.4-alpha 版本中新增，当时的名称拼写错误，为“evthread_enable_lock_debugging()”。在 2.1.2-alpha 版本中，拼写错误已修正为 evthread_enable_lock_debugging()；目前两个名称均受支持。

## 调试事件使用情况

在使用 Libevent 可以检测和报告的事件时，存在一些常见错误。这些错误包括：

- 将未初始化的结构体事件视为已初始化。

- 尝试重新初始化待处理的结构体事件。

跟踪哪些事件被初始化需要 Libevent 使用额外的内存和 CPU，因此只有在实际调试程序时才应该启用调试模式。

**Interface**
```c
void event_debug_unassign(struct event *ev);
```

当未启用调试功能时，调用 event_debug_unassign() 无效。

**例子**
```c
#include <event2/event.h>
#include <event2/event_struct.h>

#include <stdlib.h>

void cb(evutil_socket_t fd, short what, void *ptr)
{
    /* We pass 'NULL' as the callback pointer for the heap allocated
     * event, and we pass the event itself as the callback pointer
     * for the stack-allocated event. */
    struct event *ev = ptr;

    if (ev)
        event_debug_unassign(ev);
}

/* Here's a simple mainloop that waits until fd1 and fd2 are both
 * ready to read. */
void mainloop(evutil_socket_t fd1, evutil_socket_t fd2, int debug_mode)
{
    struct event_base *base;
    struct event event_on_stack, *event_on_heap;

    if (debug_mode)
       event_enable_debug_mode();

    base = event_base_new();

    event_on_heap = event_new(base, fd1, EV_READ, cb, NULL);
    event_assign(&event_on_stack, base, fd2, EV_READ, cb, &event_on_stack);

    event_add(event_on_heap, NULL);
    event_add(&event_on_stack, NULL);

    event_base_dispatch(base);

    event_free(event_on_heap);
    event_base_free(base);
}
```

详细事件调试功能只能在编译时使用 CFLAGS 环境变量“-DUSE_DEBUG”启用。启用此标志后，任何使用 Libevent 编译的程序都会输出非常详细的日志，记录后端底层活动。这些日志包括但不限于以下内容：

- 新增活动
- 事件删除
- 平台特定事件通知信息

此功能无法通过 API 调用启用或禁用，因此只能在开发者版本中使用。

这些调试功能是在 Libevent 2.0.4-alpha 版本中添加的。

## 检测 Libevent 的版本

Libevent 的新版本可能会添加新功能并修复错误。有时您需要检测 Libevent 版本，以便：

- 检测已安装的 Libevent 版本是否足以构建您的程序。
- 显示Libevent版本以进行调试。
- 检测 Libevent 的版本，以便您可以向用户发出有关错误或如何解决这些错误的信息。

**Interface**
```c
#define LIBEVENT_VERSION_NUMBER 0x02000300
#define LIBEVENT_VERSION "2.0.3-alpha"
const char *event_get_version(void);
ev_uint32_t event_get_version_number(void);
```

宏提供 Libevent 库的编译时版本；函数返回运行时版本。请注意，如果您已将程序动态链接到 Libevent，则这些版本可能不同。

Libevent 版本信息有两种格式：一种是适合向用户显示的字符串格式，另一种是适合数值比较的 4 字节整数格式。整数格式中，高字节表示主版本号，第二个字节表示次版本号，第三个字节表示补丁版本号，低字节表示发布状态（0 表示已发布，非零值表示在特定版本之后的开发系列）。

因此，已发布的 Libevent 2.0.1-alpha 的版本号为 [02 00 01 00]，即 0x02000100。介于 2.0.1-alpha 和 2.0.2-alpha 之间的开发版本可能具有 [02 00 01 08]，即 0x02000108。

**示例：编译时检查**
```c
#include <event2/event.h>

#if !defined(LIBEVENT_VERSION_NUMBER) || LIBEVENT_VERSION_NUMBER < 0x02000100
#error "This version of Libevent is not supported; Get 2.0.1-alpha or later."
#endif

int
make_sandwich(void)
{
        /* Let's suppose that Libevent 6.0.5 introduces a make-me-a
           sandwich function. */
#if LIBEVENT_VERSION_NUMBER >= 0x06000500
        evutil_make_me_a_sandwich();
        return 0;
#else
        return -1;
#endif
}
```

**示例：运行时检查**
```c
#include <event2/event.h>
#include <string.h>

int
check_for_old_version(void)
{
    const char *v = event_get_version();
    /* This is a dumb way to do it, but it is the only thing that works
       before Libevent 2.0. */
    if (!strncmp(v, "0.", 2) ||
        !strncmp(v, "1.1", 3) ||
        !strncmp(v, "1.2", 3) ||
        !strncmp(v, "1.3", 3)) {

        printf("Your version of Libevent is very old.  If you run into bugs,"
               " consider upgrading.\n");
        return -1;
    } else {
        printf("Running with Libevent version %s\n", v);
        return 0;
    }
}

int
check_version_match(void)
{
    ev_uint32_t v_compile, v_run;
    v_compile = LIBEVENT_VERSION_NUMBER;
    v_run = event_get_version_number();
    if ((v_compile & 0xffff0000) != (v_run & 0xffff0000)) {
        printf("Running with a Libevent version (%s) very different from the "
               "one we were built with (%s).\n", event_get_version(),
               LIBEVENT_VERSION);
        return -1;
    }
    return 0;
}
```

本节中的宏和函数定义在 <event2/event.h> 中。event_get_version() 函数首次出现在 Libevent 1.0c 中；其他函数首次出现在 Libevent 2.0.1-alpha 中。

## 释放全球 Libevent 结构

即使您已经释放了所有使用 Libevent 分配的对象，仍然会有一些全局分配的结构体残留。这通常不是问题：进程退出后，它们都会被清理掉。但是，这些结构体的存在可能会让一些调试工具误认为 Libevent 存在资源泄漏。如果您需要确保 Libevent 已释放所有内部库全局数据结构，可以调用：

**Interface**
```c
void libevent_global_shutdown(void);
```

此函数不会释放 Libevent 函数返回的任何结构体。如果您想在退出前释放所有内容，则需要自行释放所有事件、事件基类、缓冲区事件等。

调用 `libevent_global_shutdown()` 会导致其他 Libevent 函数的行为不可预测；除非它是程序调用的最后一个 Libevent 函数，否则请勿调用它。但有一个例外：`libevent_global_shutdown()` 是幂等的，即使它已经被调用过，再次调用也是可以的。

该函数在 <event2/event.h> 中声明。它是在 Libevent 2.1.1-alpha 版本中引入的。
