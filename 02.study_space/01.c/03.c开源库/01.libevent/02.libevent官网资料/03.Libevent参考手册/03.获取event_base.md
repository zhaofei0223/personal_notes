在使用任何 Libevent 函数之前，您需要分配一个或多个 event_base 结构体。每个 event_base 结构体都包含一组事件，并且可以通过轮询来确定哪些事件处于活动状态。

如果事件基址 (event_base) 配置为使用锁，则可以在多个线程之间安全地访问它。但是，它的循环只能在单个线程中运行。如果要让多个线程轮询 I/O，则需要为每个线程创建一个事件基址。

**提示**

> [未来版本的 Libevent 可能会支持跨多个线程运行事件的 event_base。]

每个 event_base 都有一个“方法”（method），或者说一个后端，用于确定哪些事件已准备就绪。已知的方法有：

- select
- poll
- epoll
- kqueue
- devpoll
- evport
- win32

用户可以通过环境变量禁用特定的后端。例如，如果要关闭 kqueue 后端，请设置 EVENT_NOKQUEUE 环境变量，以此类推。如果要从程序内部关闭后端，请参阅下文关于 event_config_avoid_method() 的说明。

## Setting up a default event_base

`event_base_new()` 函数会分配并返回一个具有默认设置的新事件基。它会检查环境变量，并返回指向新事件基的指针。如果出现错误，则返回 NULL。

在选择方法时，它会选择操作系统支持的最快方法。

**Interface**
```c
struct event_base *event_base_new(void);
```

对于大多数程序来说，这就足够了。

event_base_new() 函数在 <event2/event.h> 中声明。它首次出现在 Libevent 1.4.3 中。

## Setting up a complicated event_base

如果您想要更精确地控制事件基的类型，则需要使用事件配置（event_config）。事件配置是一个不透明的结构体，其中包含有关您对事件基的偏好设置的信息。当您需要一个事件基时，可以将事件配置传递给 `event_base_new_with_config()` 函数。

**Interface**
```c
struct event_config *event_config_new(void);
struct event_base *event_base_new_with_config(const struct event_config *cfg);
void event_config_free(struct event_config *cfg);
```

要使用这些函数分配一个 event_base，首先需要调用 event_config_new() 来分配一个新的 event_config。然后，调用 event_config 上的其他函数来告知它你的需求。最后，调用 event_base_new_with_config() 来获取一个新的 event_base。完成后，可以使用 event_config_free() 来释放 event_config。

**Interface**
```c
int event_config_avoid_method(struct event_config *cfg, const char *method);

enum event_method_feature {
    EV_FEATURE_ET = 0x01,
    EV_FEATURE_O1 = 0x02,
    EV_FEATURE_FDS = 0x04,
};
int event_config_require_features(struct event_config *cfg,
                                  enum event_method_feature feature);

enum event_base_config_flag {
    EVENT_BASE_FLAG_NOLOCK = 0x01,
    EVENT_BASE_FLAG_IGNORE_ENV = 0x02,
    EVENT_BASE_FLAG_STARTUP_IOCP = 0x04,
    EVENT_BASE_FLAG_NO_CACHE_TIME = 0x08,
    EVENT_BASE_FLAG_EPOLL_USE_CHANGELIST = 0x10,
    EVENT_BASE_FLAG_PRECISE_TIMER = 0x20
};
int event_config_set_flag(struct event_config *cfg,
    enum event_base_config_flag flag);
```

调用 `event_config_avoid_method` 会指示 Libevent 避免使用指定的后端。调用 `event_config_require_feature()` 会指示 Libevent 不要使用任何无法提供指定功能集全部内容的后端。调用 `event_config_set_flag()` 会指示 Libevent 在构建事件基时设置以下一个或多个运行时标志。

### event_config_require_features 的已识别特征值为：

EV_FEATURE_ET

&nbsp;&nbsp;&nbsp;&nbsp;需要支持边沿触发 I/O 的后端方法。

EV_FEATURE_O1

&nbsp;&nbsp;&nbsp;&nbsp;需要一个后端方法，其中添加或删除单个事件，或使单个事件变为活动状态，都是 O(1) 操作。

EV_FEATURE_FDS

&nbsp;&nbsp;&nbsp;&nbsp;需要一个能够支持任意文件描述符类型（而不仅仅是套接字）的后端方法。

### event_config_set_flag() 函数的可用选项值为：

EVENT_BASE_FLAG_NOLOCK

&nbsp;&nbsp;&nbsp;&nbsp;不要为 event_base 分配锁。启用此选项可能会节省一些锁定和释放 event_base 的时间，但会使从多个线程访问它变得不安全且无法正常工作。

EVENT_BASE_FLAG_IGNORE_ENV

&nbsp;&nbsp;&nbsp;&nbsp;选择后端方法时，请勿检查 EVENT_* 环境变量。使用此标志前请慎重考虑：它可能会增加用户调试程序与 Libevent 之间交互的难度。

EVENT_BASE_FLAG_STARTUP_IOCP

&nbsp;&nbsp;&nbsp;&nbsp;仅在 Windows 系统上，此标志使 Libevent 在启动时启用任何必要的 IOCP 调度逻辑，而不是按需启用。

EVENT_BASE_FLAG_NO_CACHE_TIME

&nbsp;&nbsp;&nbsp;&nbsp;不要每次事件循环准备运行超时回调时都检查当前时间，而是在每次超时回调后检查。这样做可能会占用比预期更多的 CPU 资源，所以要注意！

EVENT_BASE_FLAG_EPOLL_USE_CHANGELIST

&nbsp;&nbsp;&nbsp;&nbsp;告诉 Libevent，如果它决定使用 epoll 后端，那么使用速度更快的基于“变更列表”的后端是安全的。epoll-changelist 后端可以避免在同一个文件描述符 (fd) 的状态在两次调用后端分发函数之间被多次修改时产生的不必要的系统调用，但它也会触发一个内核错误，如果您将任何由 dup() 或其变体克隆的文件描述符提供给 Libevent，则会导致错误的结果。如果您使用 epoll 以外的后端，此标志无效。您还可以通过设置 EVENT_EPOLL_USE_CHANGELIST 环境变量来启用 epoll-changelist 选项。

EVENT_BASE_FLAG_PRECISE_TIMER

&nbsp;&nbsp;&nbsp;&nbsp;默认情况下，Libevent 会尝试使用操作系统提供的最快的计时机制。如果存在速度较慢但精度更高的计时机制，此标志会指示 Libevent 使用该机制。如果操作系统没有提供这种速度较慢但精度更高的机制，则此标志无效。

上述操作 event_config 的函数，成功时返回 0，失败时返回 -1。

**笔记**

> 很容易设置一个需要操作系统不支持的后端的 event_config。例如，截至 Libevent 2.0.1-alpha 版本，Windows 系统没有 O(1) 后端，Linux 系统也没有同时支持 EV_FEATURE_FDS 和 EV_FEATURE_O1 的后端。如果您创建的配置 Libevent 无法满足，event_base_new_with_config() 函数将返回 NULL。

**Interface**
```c
int event_config_set_num_cpus_hint(struct event_config *cfg, int cpus)
```

目前，此函数仅在 Windows 系统使用 IOCP 时有效，但未来可能会支持其他平台。调用此函数会指示 event_config，其生成的 event_base 在多线程运行时应尽可能利用指定数量的 CPU。请注意，这只是一个建议：实际事件基类使用的 CPU 数量可能多于或少于您选择的数量。

**Interface**
```c
int event_config_set_max_dispatch_interval(struct event_config *cfg,
    const struct timeval *max_interval, int max_callbacks,
    int min_priority);
```

此函数通过限制在检查是否存在更高优先级事件之前可以调用的低优先级事件回调次数，来防止优先级反转。如果 `max_interval` 不为空，事件循环会在每次回调后检查时间，如果超过 `max_interval`，则会重新扫描是否存在更高优先级事件。如果 `max_callbacks` 为非负数，事件循环还会在调用 `max_callbacks` 个回调后检查是否存在更多事件。这些规则适用于优先级为 `min_priority` 或更高的任何事件。

**例如：优先选择边缘触发的后端**
```c
struct event_config *cfg;
struct event_base *base;
int i;

/* My program wants to use edge-triggered events if at all possible.  So
   I'll try to get a base twice: Once insisting on edge-triggered IO, and
   once not. */
for (i=0; i<2; ++i) {
    cfg = event_config_new();

    /* I don't like select. */
    event_config_avoid_method(cfg, "select");

    if (i == 0)
        event_config_require_features(cfg, EV_FEATURE_ET);

    base = event_base_new_with_config(cfg);
    event_config_free(cfg);
    if (base)
        break;

    /* If we get here, event_base_new_with_config() returned NULL.  If
       this is the first time around the loop, we'll try again without
       setting EV_FEATURE_ET.  If this is the second time around the
       loop, we'll give up. */
}
```

**示例：避免优先级反转**
```c
struct event_config *cfg;
struct event_base *base;

cfg = event_config_new();
if (!cfg)
   /* Handle error */;

/* I'm going to have events running at two priorities.  I expect that
   some of my priority-1 events are going to have pretty slow callbacks,
   so I don't want more than 100 msec to elapse (or 5 callbacks) before
   checking for priority-0 events. */
struct timeval msec_100 = { 0, 100*1000 };
event_config_set_max_dispatch_interval(cfg, &msec_100, 5, 1);

base = event_base_new_with_config(cfg);
if (!base)
   /* Handle error */;

event_base_priority_init(base, 2);
```

这些函数和类型在<event2/event.h>中声明。

EVENT_BASE_FLAG_IGNORE_ENV 标志首次出现在 Libevent 2.0.2-alpha 版本中。EVENT_BASE_FLAG_PRECISE_TIMER 标志首次出现在 Libevent 2.1.2-alpha 版本中。event_config_set_num_cpus_hint() 函数是 Libevent 2.0.7-rc 版本新增的，event_config_set_max_dispatch_interval() 函数是 2.1.1-alpha 版本新增的。本节中的其他所有内容均首次出现在 Libevent 2.0.1-alpha 版本中。

## 检查 event_base 的后端方法

有时你想查看 event_base 中实际有哪些功能可用，或者它使用了哪种方法。

**Interface**
```c
const char **event_get_supported_methods(void);
```

event_get_supported_methods() 函数返回一个指向 Libevent 此版本支持的方法名称数组的指针。数组中的最后一个元素为 NULL。

**例子**
```c
int i;
const char **methods = event_get_supported_methods();
printf("Starting Libevent %s.  Available methods are:\n",
    event_get_version());
for (i=0; methods[i] != NULL; ++i) {
    printf("    %s\n", methods[i]);
}
```

**笔记**

> 此函数返回 Libevent 编译时支持的方法列表。但您的操作系统可能并非在 Libevent 运行时支持所有方法。例如，您可能使用的是某个版本的 macOS，其中 kqueue 存在太多 bug 而无法使用。

**Interface**
```c
const char *event_base_get_method(const struct event_base *base);
enum event_method_feature event_base_get_features(const struct event_base *base);
```

event_base_get_method() 调用返回 event_base 实际使用的方法的名称。event_base_get_features() 调用返回它支持的功能的位掩码。

**例子**
```c
struct event_base *base;
enum event_method_feature f;

base = event_base_new();
if (!base) {
    puts("Couldn't get an event_base!");
} else {
    printf("Using Libevent with backend method %s.",
        event_base_get_method(base));
    f = event_base_get_features(base);
    if ((f & EV_FEATURE_ET))
        printf("  Edge-triggered events are supported.");
    if ((f & EV_FEATURE_O1))
        printf("  O(1) event notification is supported.");
    if ((f & EV_FEATURE_FDS))
        printf("  All FD types are supported.");
    puts("");
}
```

这些函数定义在 <event2/event.h> 中。event_base_get_method() 调用最早在 Libevent 1.4.3 中可用。其他函数最早出现在 Libevent 2.0.1-alpha 中。

## 释放 event_base

当您不再需要 event_base 时，可以使用 event_base_free() 将其释放。

**Interface**
```c
void event_base_free(struct event_base *base);
```

请注意，此函数不会释放当前与 event_base 关联的任何事件，也不会关闭它们的任何套接字，或释放它们的任何指针。

event_base_free() 函数定义在 <event2/event.h> 中。它最初是在 Libevent 1.2 中实现的。

## 基于事件设置优先级

Libevent 支持为事件设置多个优先级。但默认情况下，一个 event_base 仅支持一个优先级。您可以通过调用 event_base_priority_init() 来设置 event_base 的优先级数量。

**Interface**
```c
int event_base_priority_init(struct event_base *base, int n_priorities);
```

此函数成功返回 0，失败返回 -1。`base`参数是要修改的 `event_base`，`n_priorities` 参数是要支持的优先级数量，必须至少为 1。新事件的可用优先级将从 0（最重要）到 n_priorities-1（最不重要）进行编号。

存在一个常量 EVENT_MAX_PRIORITIES，它设置了 n_priorities 值的上限。如果 n_priorities 的值高于此上限，则调用此函数会出错。

**笔记**

必须在任何事件激活之前调用此函数。最好在创建 event_base 之后立即调用它。

要查找当前由基地支持的优先级数量，您可以调用 event_base_getnpriorities()。

**Interface**
```c
int event_base_get_npriorities(struct event_base *base);
```

返回值等于基类中配置的优先级数量。因此，如果 event_base_get_npriorities() 返回 3，则允许的优先级值为 0、1 和 2。

**例子**
```c
For an example, see the documentation for event_priority_set below.
```

默认情况下，与此基地关联的所有新事件的优先级将初始化为 n_priorities / 2。

event_base_priority_init 函数定义在 <event2/event.h> 中。它自 Libevent 1.0 起就可用。event_base_get_npriorities() 函数是 Libevent 2.1.1-alpha 中的新增函数。

## 在 fork() 之后重新初始化 event_base

并非所有事件后端在调用 fork() 后都能保持干净的持久化状态。因此，如果您的程序使用 fork() 或相关的系统调用来启动新进程，并且您希望在 fork 后继续使用 event_base，则可能需要重新初始化它。

**Interface**
```c
int event_reinit(struct event_base *base);
```

该函数成功时返回 0，失败时返回 -1。

**例子**
```c
struct event_base *base = event_base_new();

/* ... add some events to the event_base ... */

if (fork()) {
    /* In parent */
    continue_running_parent(base); /*...*/
} else {
    /* In child */
    event_reinit(base);
    continue_running_child(base); /*...*/
}
```

event_reinit() 函数定义在 <event2/event.h> 中。它最初在 Libevent 1.4.3-alpha 中可用。

## 已过时的 event_base 函数

旧版本的 Libevent 非常依赖于“当前”事件基址的概念。“当前”事件基址是一个全局设置，所有线程共享。如果您忘记指定所需的事件基址，则会使用当前事件基址。由于事件基址并非线程安全，因此很容易出错。

而不是 event_base_new()，而是：

**Interface**
```c
struct event_base *event_init(void);
```

这个函数的作用类似于 event_base_new()，它会将当前基址设置为已分配的基址。没有其他方法可以更改当前基址。

本节中的一些 event_base 函数有针对当前基类进行操作的变体。这些函数的行为与当前函数相同，只是它们不接受基类参数。
