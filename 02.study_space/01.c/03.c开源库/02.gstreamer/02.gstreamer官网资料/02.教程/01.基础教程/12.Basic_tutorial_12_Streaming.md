# 基础教程 12：流媒体

## 目标

直接从互联网播放媒体文件而不将其存储在本地称为流媒体播放。在之前的教程中，每当我们使用以 `<url>` 开头的 URI 时，我们都在进行流媒体播放http://。本教程将介绍流媒体播放时需要注意的几个要点。具体来说：

- 如何启用缓冲（以缓解网络问题）
- 如何从中断（时钟丢失）中恢复

## 介绍

在流媒体播放过程中，媒体数据块一旦从网络到达，就会立即被解码并排队等待播放。这意味着，如果某个数据块延迟（这在互联网上并不罕见），播放队列可能会被清空，导致媒体播放中断。

通用的解决方案是建立一个“缓冲区”，即在开始播放前允许一定数量的媒体片段排队等待。这样一来，播放开始时间会稍有延迟，但即使某些片段延迟加载，也不会影响播放，因为队列中还有更多片段在等待。

事实证明，GStreamer 已经实现了这个解决方案，但之前的教程并没有用到它。GStreamer 中的某些元素，例如 `<buffer>`queue2和` multiqueue<buffer> playbin`，能够构建缓冲区并发布关于缓冲区级别（队列状态）的总线消息。因此，想要提高网络稳定性的应用程序应该监听这些消息，并在缓冲区级别不足时（通常低于 100%）暂停播放。

为了实现多个接收器（例如音频和视频接收器）之间的同步，需要使用全局时钟。GStreamer 会从所有能够提供时钟的元素中选择一个作为该时钟。在某些情况下，例如 RTP 源切换流或更改输出设备时，该时钟可能会丢失，需要选择一个新的时钟。这种情况主要发生在处理流媒体时，因此本教程将详细介绍这一过程。

当时钟丢失时，应用程序会收到总线上的消息；要选择一个新的时钟，应用程序只需将管道设置为， PAUSED然后PLAYING再设置为即可。

## 网络弹性示例

将此代码复制到名为 . 的文本文件中basic-tutorial-12.c。

基础教程-12.c

```c
#include <gst/gst.h>
#include <string.h>

#ifdef __APPLE__
#include <TargetConditionals.h>
#endif

typedef struct _CustomData
{
  gboolean is_live;
  GstElement *pipeline;
  GMainLoop *loop;
} CustomData;

static void
cb_message (GstBus * bus, GstMessage * msg, CustomData * data)
{

  switch (GST_MESSAGE_TYPE (msg)) {
    case GST_MESSAGE_ERROR:{
      GError *err;
      gchar *debug;

      gst_message_parse_error (msg, &err, &debug);
      g_print ("Error: %s\n", err->message);
      g_error_free (err);
      g_free (debug);

      gst_element_set_state (data->pipeline, GST_STATE_READY);
      g_main_loop_quit (data->loop);
      break;
    }
    case GST_MESSAGE_EOS:
      /* end-of-stream */
      gst_element_set_state (data->pipeline, GST_STATE_READY);
      g_main_loop_quit (data->loop);
      break;
    case GST_MESSAGE_BUFFERING:{
      gint percent = 0;

      /* If the stream is live, we do not care about buffering. */
      if (data->is_live)
        break;

      gst_message_parse_buffering (msg, &percent);
      g_print ("Buffering (%3d%%)\r", percent);
      /* Wait until buffering is complete before start/resume playing */
      if (percent < 100)
        gst_element_set_state (data->pipeline, GST_STATE_PAUSED);
      else
        gst_element_set_state (data->pipeline, GST_STATE_PLAYING);
      break;
    }
    case GST_MESSAGE_CLOCK_LOST:
      /* Get a new clock */
      gst_element_set_state (data->pipeline, GST_STATE_PAUSED);
      gst_element_set_state (data->pipeline, GST_STATE_PLAYING);
      break;
    default:
      /* Unhandled message */
      break;
  }
}

int
tutorial_main (int argc, char *argv[])
{
  GstElement *pipeline;
  GstBus *bus;
  GstStateChangeReturn ret;
  GMainLoop *main_loop;
  CustomData data;

  /* Initialize GStreamer */
  gst_init (&argc, &argv);

  /* Initialize our data structure */
  memset (&data, 0, sizeof (data));

  /* Build the pipeline */
  pipeline =
      gst_parse_launch
      ("playbin uri=https://gstreamer.freedesktop.org/data/media/sintel_trailer-480p.webm",
      NULL);
  bus = gst_element_get_bus (pipeline);

  /* Start playing */
  ret = gst_element_set_state (pipeline, GST_STATE_PLAYING);
  if (ret == GST_STATE_CHANGE_FAILURE) {
    g_printerr ("Unable to set the pipeline to the playing state.\n");
    gst_object_unref (pipeline);
    return -1;
  } else if (ret == GST_STATE_CHANGE_NO_PREROLL) {
    data.is_live = TRUE;
  }

  main_loop = g_main_loop_new (NULL, FALSE);
  data.loop = main_loop;
  data.pipeline = pipeline;

  gst_bus_add_signal_watch (bus);
  g_signal_connect (bus, "message", G_CALLBACK (cb_message), &data);

  g_main_loop_run (main_loop);

  /* Free resources */
  g_main_loop_unref (main_loop);
  gst_object_unref (bus);
  gst_element_set_state (pipeline, GST_STATE_NULL);
  gst_object_unref (pipeline);
  return 0;
}

int
main (int argc, char *argv[])
{
#if defined(__APPLE__) && TARGET_OS_MAC && !TARGET_OS_IPHONE
  return gst_macos_main ((GstMainFunc) tutorial_main, argc, argv, NULL);
#else
  return tutorial_main (argc, argv);
#endif
}
```

## 攻略

本教程唯一特别之处在于对特定消息做出反应；因此，初始化代码非常简单，现在应该很容易理解。唯一的新内容是检测实时流：

```c
/* Start playing */
ret = gst_element_set_state (pipeline, GST_STATE_PLAYING);
if (ret == GST_STATE_CHANGE_FAILURE) {
  g_printerr ("Unable to set the pipeline to the playing state.\n");
  gst_object_unref (pipeline);
  return -1;
} else if (ret == GST_STATE_CHANGE_NO_PREROLL) {
  data.is_live = TRUE;
}
```

直播流无法暂停，因此它们的行为PAUSED与处于非PLAYING直播状态时相同。将直播流设置为非直播状态会PAUSED成功，但返回的是 `NULL`GST_STATE_CHANGE_NO_PREROLL而不是 `READY`，以 表明这是一个直播流。即使我们尝试将管道设置为 `READY` ，GST_STATE_CHANGE_SUCCESS也会收到返回码 `NULL` ，因为状态更改是逐步发生的（从 `NULL` 到 `READY`，再到 `READY`，最后到`READY` ）。NO_PREROLLPLAYINGPAUSEDPLAYING

我们关注直播流是因为我们想禁用它们的缓冲，所以我们将结果记录gst_element_set_state()在变量中 is_live。

现在让我们回顾一下消息解析回调函数中比较有趣的部分：

```c
case GST_MESSAGE_BUFFERING: {
  gint percent = 0;

  /* If the stream is live, we do not care about buffering. */
  if (data->is_live) break;

  gst_message_parse_buffering (msg, &percent);
  g_print ("Buffering (%3d%%)\r", percent);
  /* Wait until buffering is complete before start/resume playing */
  if (percent < 100)
    gst_element_set_state (data->pipeline, GST_STATE_PAUSED);
  else
    gst_element_set_state (data->pipeline, GST_STATE_PLAYING);
  break;
}
```

首先，如果这是实时源，请忽略缓冲消息。

我们解析缓冲消息以gst_message_parse_buffering()检索缓冲级别。

然后，我们在控制台上打印缓冲级别，PAUSED如果低于 100%，则将管道设置为 。否则，将管道设置为 PLAYING。

启动时，我们会看到缓冲级别在播放开始前上升到 100%，这正是我们想要达到的效果。如果之后网络速度变慢或无响应，导致缓冲区耗尽，我们会收到缓冲级别低于 100% 的新消息，因此我们会再次暂停播放流程，直到积累足够的缓冲区为止。

```c
case GST_MESSAGE_CLOCK_LOST:
  /* Get a new clock */
  gst_element_set_state (data->pipeline, GST_STATE_PAUSED);
  gst_element_set_state (data->pipeline, GST_STATE_PLAYING);
  break;
```

对于第二个网络问题，即时钟丢失，我们只需将管道设置为，PAUSED然后再设置回PLAYING，以便选择一个新的时钟，并在必要时等待接收新的媒体块。

## 结论

本教程介绍了如何通过两个非常简单的预防措施来增强应用程序的网络弹性：

- 负责缓冲管道发送的消息。
- 处理时钟丢失

处理这些消息可以改善应用程序对网络问题的响应，从而提高整体播放流畅度。
