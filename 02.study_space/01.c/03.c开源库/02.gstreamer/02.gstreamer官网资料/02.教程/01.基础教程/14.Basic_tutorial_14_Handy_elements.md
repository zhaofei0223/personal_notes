# 基础教程 14：实用元素

## 目标

本教程列出了一些值得了解的实用 GStreamer 元素。它们涵盖了从功能强大的多合一元素（例如 `GStreamer.apply` playbin）到调试时非常有用的辅助元素。这些元素功能强大，可轻松构建复杂的管道。

为简单起见，以下示例均使用该 gst-launch-1.0工具（有关该工具的更多信息，请参阅 基础教程 10：GStreamer 工具）。-v如果您想查看正在协商的焊盘电容，请使用命令行参数。

## Bins

这些是 Bin 元素，您可以将其视为单个元素，它们负责实例化所有必要的内部管道以完成其任务。

**playbin**

本组件在整个教程中被广泛使用。它管理媒体播放的各个方面，从源到显示，包括解复用和解码。它非常灵活，选项众多，因此我们专门制作了一整套教程来讲解它。更多详情请参阅“播放”教程。

**uridecodebin**

此元素将 URI 中的数据解码为原始媒体。它会选择一个能够处理给定 URI 方案的源元素，并将其连接到一个decodebin元素。它的作用类似于解复用器，因此它会提供与媒体中流的数量相同的源填充。

```shell
gst-launch-1.0 uridecodebin uri=https://gstreamer.freedesktop.org/data/media/sintel_trailer-480p.webm ! videoconvert ! autovideosink
```

```shell
gst-launch-1.0 uridecodebin uri=https://gstreamer.freedesktop.org/data/media/sintel_trailer-480p.webm ! audioconvert ! autoaudiosink
```

**decodebin**

该元素通过自动插拔的方式，利用可用的解码器和解复用器自动构建解码管道，直至获取原始媒体。它在内部被使用，uridecodebin通常使用起来更方便，因为它还会创建一个合适的源元素。它会替换旧的decodebin元素。它的作用类似于解复用器，因此会提供与媒体中流数量相同的源填充。

```shell
gst-launch-1.0 souphttpsrc location=https://gstreamer.freedesktop.org/data/media/sintel_trailer-480p.webm ! decodebin ! autovideosink
```

## 文件输入/输出

**filesrc**

此元素读取本地文件并生成带有ANYCaps 的媒体。如果要获取媒体的正确 Caps，请使用typefind元素浏览流或将typefind属性设置filesrc为 TRUE。

```shell
gst-launch-1.0 filesrc location=f:\\media\\sintel\\sintel_trailer-480p.webm ! decodebin ! autovideosink
```

**filesink**

此元素会将接收到的所有媒体文件写入文件。使用 location属性指定文件名。

```shell
gst-launch-1.0 audiotestsrc ! vorbisenc ! oggmux ! filesink location=test.ogg
```

## 网络

**souphttpsrc**

此元素使用libsoup库，通过 HTTP 协议以客户端身份从网络接收数据。可通过属性设置要检索数据的 URL location 。

```shell
gst-launch-1.0 souphttpsrc location=https://gstreamer.freedesktop.org/data/media/sintel_trailer-480p.webm ! decodebin ! autovideosink
```

## 测试介质生成

这些元素对于检查管道的其他部分是否正常工作非常有用，只需将源替换为这些“保证”可以工作的测试源之一即可。

**videotestsrc**

此元素会生成一个视频图案（可通过pattern属性选择多种不同选项）。可用于测试视频管道。

```shell
gst-launch-1.0 videotestsrc ! videoconvert ! autovideosink
```

**audiotestsrc**

此元素会生成音频波形（可通过wave属性选择多种不同的选项）。可用于测试音频管道。

```shell
gst-launch-1.0 audiotestsrc ! audioconvert ! autoaudiosink
```

## 视频适配器

**videoconvert**

该元素可将一种颜色空间（例如 RGB）转换为另一种颜色空间（例如 YUV）。它还可以在不同的 YUV 格式（例如 I420、NV12、YUY2 等）或 RGB 格式排列（例如 RGBA、ARGB、BGRA 等）之间进行转换。

这通常是解决谈判问题的首选方案。当不需要谈判时，由于其上游和下游元素之间已经可以相互理解，它会以直通模式运行，对性能的影响极小。

一般来说，videoconvert当使用在设计时 Caps 未知的元素时，例如autovideosink，或者可以根据外部因素（例如解码用户提供的文件）而变化的元素时，总是应该使用。

```shell
gst-launch-1.0 videotestsrc ! videoconvert ! autovideosink
```

**videorate**

该元件接收一串带有时间戳的视频帧，并生成一个与源垫帧速率相匹配的视频流。校正过程通过丢弃和复制帧来实现，没有使用任何复杂的帧插值算法。

这有助于连接帧速率不同的元素。与其他适配器一样，如果不需要此功能（因为两个平板电脑都能使用相同的帧速率），它将以直通模式运行，不会影响性能。

因此，为了以防万一，在设计时如果实际帧速率未知，最好始终使用它。

```shell
gst-launch-1.0 videotestsrc ! video/x-raw,framerate=30/1 ! videorate ! video/x-raw,framerate=1/1 ! videoconvert ! autovideosink
```

**videoscale**

此元素用于调整视频帧的大小。默认情况下，该元素会尝试将源和目标 Pad 上的帧大小协商为相同大小，从而避免缩放。因此，如果不需要缩放，则可以安全地将此元素插入到管道中，以获得更稳定的性能，而不会增加任何额外开销。

该元素支持多种颜色空间，包括各种 YUV 和 RGB 格式，因此通常能够在流程中的任何位置运行。

如果视频要输出到用户可控制大小的窗口，最好使用 <video>videoscale元素，因为并非所有视频接收器都能够执行缩放操作。

```shell
gst-launch-1.0 uridecodebin uri=https://gstreamer.freedesktop.org/data/media/sintel_trailer-480p.webm ! videoscale ! video/x-raw,width=178,height=100 ! videoconvert ! autovideosink
```

## 音频适配器

**audioconvert**

该元素可在各种可能的格式之间转换原始音频缓冲区。它支持整数到浮点数的转换、宽度/深度转换、符号性和字节序转换以及声道转换。

就像videoconvert视频一样，你可以用它来解决音频中的协商问题，而且通常可以随意使用，因为如果不需要，这个元素什么也不做。

```shell
gst-launch-1.0 audiotestsrc ! audioconvert ! autoaudiosink
```

**audioresample**

该元素使用可配置的窗口函数将原始音频缓冲区重新采样到不同的采样率，以提高音质。

再次强调，要用它来解决有关抽样率的谈判问题，并且不要害怕慷慨地使用它。

```shell
gst-launch-1.0 uridecodebin uri=https://gstreamer.freedesktop.org/data/media/sintel_trailer-480p.webm ! audioresample ! audio/x-raw,rate=4000 ! audioconvert ! autoaudiosink
```

**audiorate**

该元素接收一串带有时间戳的原始音频帧，并通过根据需要插入或删除采样点来生成完美的音频流。它不像其他元素那样允许更改采样率videorate，而是填充空白并删除重叠的采样点，从而使输出流连续且“干净”。

在时间戳会丢失的情况下（例如，存储为某些文件格式时），如果接收方要求所有样本都存在，那么这种方法就很有用。由于举例说明比较繁琐，因此这里不提供示例。

警告大多数时候，audiorate这并非你所愿。

## 多线程

**queue**

队列的概念已在基础教程 7：多线程和填充可用性中进行了讲解。简而言之，队列执行两项任务：

- 数据会被放入队列，直到达到设定的上限。任何向队列中添加更多缓冲区的操作都会阻塞推送线程，直到有更多空间可用。
- 该队列在源 Pad 上创建一个新线程，以解耦接收器 Pad 和源 Pad 上的处理。

此外，queue当缓冲区即将为空或为满时（根据一些可配置的阈值），它会触发信号；并且可以被指示在缓冲区为满时丢弃缓冲区而不是阻塞。

一般来说，如果网络缓冲对您来说不是问题，则应优先选择更简单的queue元素。 有关示例，请参阅基础教程 7：多线程和填充可用性。queue2

**queue2**

这个元素并非现有元素的演进queue。它与现有元素有着相同的设计目标，但采用了不同的实现方式，因此功能也有所不同。遗憾的是，通常很难判断哪个队列才是最佳选择。

queue2它执行上述两项任务queue，此外，还能将接收到的数据（或部分数据）存储在磁盘文件中，以便稍后检索。它还将信号替换为 基础教程 12：流式传输中描述的更通用、更方便的缓冲消息。

一般来说，如果网络缓冲是您关注的问题，则应优先选择queue2流媒体。 有关示例，请参阅基础教程 12：流媒体（隐藏在内部）。queuequeue2playbin

**multiqueue**

该元素为多个数据流同时提供队列，并通过以下方式简化了管理：允许某些队列在其他数据流未接收数据时增长，或者允许某些队列在未连接到任何数据流时丢弃数据（而不是像更简单的队列那样返回错误）。此外，它还同步不同的数据流，确保任何一个数据流都不会领先于其他数据流太多。

这是一个高级元素。它位于内部decodebin，但在普通的播放应用程序中，您很少需要自己实例化它。

**tee**

基础教程 7：多线程和数据位可用性已经演示了如何使用一个tee元素将数据拆分到多个数据位。拆分数据流非常有用，例如在录制视频时，视频既要在屏幕上显示，也要进行编码并写入文件。另一个例子是播放音乐并连接可视化模块。

需要queue在每个分支中使用独立的元素，以便为每个分支提供独立的线程。否则，一个分支的数据流阻塞会导致其他分支也停滞不前。

```shell
gst-launch-1.0 audiotestsrc ! tee name=t ! queue ! audioconvert ! autoaudiosink t. ! queue ! wavescope ! videoconvert ! autovideosink
```

## 能力

**capsfilter**

基础教程 10：GStreamer 工具已经讲解了如何使用 Caps 过滤器gst-launch-1.0。在以编程方式构建管道时，Caps 过滤器通过 `<caps-filter>` 元素实现capsfilter。此元素本身不会修改数据，而是对数据格式进行限制。

```
gst-launch-1.0 videotestsrc ! video/x-raw, format=GRAY8 ! videoconvert ! autovideosink
```

**typefind**

此元素决定流中包含的媒体类型。它按优先级顺序应用类型查找函数。检测到类型后，它会将源 Pad Caps 设置为找到的媒体类型并发出信号have-type。

它由内部实例化decodebin，您也可以使用它来查找媒体类型，尽管通常可以使用 GstDiscoverer提供更多信息的（如 基本教程 9：媒体信息收集中所示）。

## 调试

**fakesink**

这个接收器元素会直接接收所有输入的数据。在调试时，它非常有用，可以替换掉你常用的接收器，排除它们的干扰。当它与开关一起使用时-v，可能会产生大量冗余信息gst-launch-1.0，因此请使用相应silent的属性来消除这些不必要的噪音。

```shell
gst-launch-1.0 audiotestsrc num-buffers=1000 ! fakesink sync=false
```

**identity**

这是一个虚拟元素，它会原封不动地传递传入的数据。它具有一些有用的诊断功能，例如偏移量和时间戳检查，以及缓冲区丢弃。请阅读其文档，了解这个看似无害的元素所能执行的所有操作。

```shell
gst-launch-1.0 audiotestsrc ! identity drop-probability=0.1 ! audioconvert ! autoaudiosink
```
