# Buffers and Events

流经管道的数据由缓冲区和事件组成。缓冲区包含实际的媒体数据。事件包含控制信息，例如寻址信息和流结束通知。所有这些数据都会在管道运行时自动流经管道。本章主要目的是向您解释这个概念；您无需进行任何实际操作。

## Buffers

缓冲区包含将流经您创建的管道的数据。源元素通常会创建一个新的缓冲区，并通过一个垫片将其传递给链中的下一个元素。使用 GStreamer 基础架构创建媒体管道时，您无需自行处理缓冲区；元素会自动为您完成这项工作。

缓冲区由以下部分组成：

- 指向内存对象的指针。内存对象封装了内存中的一个区域。
- 缓冲区的时间戳。
- 引用计数，指示有多少元素正在使用此缓冲区。当没有元素引用该缓冲区时，将使用此引用计数来销毁缓冲区。
- 缓冲区标志。

最简单的情况是，创建一个缓冲区，分配内存，将数据放入其中，然后传递给下一个元素。该元素读取数据，执行某些操作（例如创建一个新缓冲区并进行解码），然后取消对缓冲区的引用。这会导致数据被释放，缓冲区被销毁。典型的视频或音频解码器的工作原理就是这样。

不过，还有更复杂的情况。元素可以就地修改缓冲区，即无需分配新的缓冲区。元素还可以写入硬件内存（例如来自视频捕获源的数据）或从 X 服务器分配的内存（使用 XShm）。缓冲区可以是只读的，等等。

## Events

事件是控制粒子，它们与缓冲区一起在管道中向上游和下游发送。下游事件会通知其他元素流的状态。可能的事件包括查找、刷新、流结束通知等等。上游事件既用于应用程序与元素之间的交互，也用于元素之间的交互，以请求流状态的更改，例如查找。对于应用程序而言，只有上游事件是重要的。对下游事件的解释只是为了更全面地理解数据概念。

由于大多数应用程序都以时间单位进行搜索，因此我们下面的示例也采用这种方式：

```c
static void
seek_to_time (GstElement *element,
          guint64     time_ns)
{
  GstEvent *event;

  event = gst_event_new_seek (1.0, GST_FORMAT_TIME,
                  GST_SEEK_FLAG_NONE,
                  GST_SEEK_METHOD_SET, time_ns,
                  GST_SEEK_TYPE_NONE, G_GUINT64_CONSTANT (0));
  gst_element_send_event (element, event);
}
```

这个函数gst_element_seek ()是实现此功能的快捷方式。这里主要是为了演示整个工作原理。
