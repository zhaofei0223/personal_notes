# Buffering

缓冲的目的是在管道中累积足够的数据，以便流畅无中断地播放。它通常用于从（速度较慢的）非实时网络源读取数据，但也可用于实时源。

GStreamer 支持以下使用场景：

- 在开始播放之前，将一定量的数据缓冲到内存中，以最大程度地减少网络波动的影响。参见 流媒体缓冲。
- 将网络文件下载到本地磁盘，并快速定位下载的数据。这类似于 QuickTime/YouTube 播放器。参见“下载缓冲”。
- 将（半）实时流缓存到本地磁盘上的环形缓冲区，并在缓存区域中进行查找。这类似于 TiVo 的时移功能。参见时移缓冲。

GStreamer 可以向应用程序提供有关当前缓冲状态的进度报告，还可以让应用程序决定如何缓冲以及何时停止缓冲。

最简单的情况下，应用程序需要监听总线上的 BUFFERING 消息。如果 BUFFERING 消息中的百分比指示符小于 100%，则表示管道正在缓冲。当收到百分比为 100% 的消息时，缓冲完成。在缓冲状态下，应用程序应将管道保持在 PAUSED 状态。缓冲完成后，应用程序可以将管道恢复到 PLAYING 状态。

以下示例展示了消息处理程序如何处理缓冲消息。我们将在“缓冲策略”部分看到更高级的方法。

```c
  [...]

  switch (GST_MESSAGE_TYPE (message)) {
    case GST_MESSAGE_BUFFERING:{
      gint percent;

      /* no state management needed for live pipelines */
      if (is_live)
        break;

      gst_message_parse_buffering (message, &percent);

      if (percent == 100) {
        /* a 100% message means buffering is done */
        buffering = FALSE;
        /* if the desired state is playing, go back */
        if (target_state == GST_STATE_PLAYING) {
          gst_element_set_state (pipeline, GST_STATE_PLAYING);
        }
      } else {
        /* buffering busy */
        if (!buffering && target_state == GST_STATE_PLAYING) {
          /* we were not buffering but PLAYING, PAUSE  the pipeline. */
          gst_element_set_state (pipeline, GST_STATE_PAUSED);
        }
        buffering = TRUE;
      }
      break;

  [...]
```

## Stream buffering

```json5
      +---------+     +---------+     +-------+
      | httpsrc |     | buffer  |     | demux |
      |        src - sink      src - sink     ....
      +---------+     +---------+     +-------+
```

在这种情况下，我们正在从慢速网络源读取数据到缓冲区元素（例如 queue2）。

缓冲区元素具有以字节为单位的低水位线和高水位线。缓冲区按如下方式使用水位线：

- 缓冲区元素会持续发送 BUFFERING 消息，直到达到高水位线。这会指示应用程序保持管道暂停状态，最终导致源端口在接收端预滚动数据时无法推送数据。
- 当达到高水位线时，将发布一条包含 100% 的 BUFFERING 消息，指示应用程序继续播放。
- 播放过程中，当达到低水位线时，队列会再次开始发送缓冲消息，导致应用程序再次暂停播放管道，直到再次达到高水位线。这称为重新缓冲阶段。
- 播放过程中，队列级别会在高水位线和低水位线之间波动，以此来补偿网络不稳定性。

当解复用器以推送模式运行时，可以使用这种缓冲方法。在流中进行查找需要在网络源上进行。当文件总时长未知时，例如在直播流中，或者当无法/不需要高效查找时，这种方法尤为适用。

问题在于如何配置合适的低水位线和高水位线。以下是一些建议：

- 可以测量网络带宽，并配置低/高水位线，使缓冲时间固定。GStreamer 核心中的 queue2 元素具有 max-size-time 属性，该属性与 use-rate-estimate 属性配合使用，正是实现此功能。此外，playbin 的 buffer-duration 属性也使用速率估计值来调整缓冲的数据量。
- 根据编解码器比特率，还可以设置水印，以便在播放开始前缓冲固定量的数据。通常情况下，缓冲组件并不知道流的比特率，但它可以通过查询获取该值。
- 首先使用固定数量的字节，测量重新缓冲之间的时间间隔，然后增加队列大小，直到重新缓冲之间的时间间隔在应用程序选择的限制范围内。

缓冲元件可以插入到管道中的任何位置。例如，您可以将缓冲元件插入到解码器之前。这样就可以根据时间设置低水位线/高水位线。

playbin 的缓冲标志会对解析后的数据进行缓冲。稍后进行缓冲的另一个优点是可以让解复用器以拉取模式运行。当从速度较慢的网络驱动器（使用 filesrc）读取数据时，这是一种有效的缓冲方式。

## Download buffering

```json5
      +---------+     +---------+     +-------+
      | httpsrc |     | buffer  |     | demux |
      |        src - sink      src - sink     ....
      +---------+     +----|----+     +-------+
                           V
                          file
```

如果我们知道服务器正在向客户端传输固定长度的文件，应用程序可以选择将整个文件下载到磁盘。缓冲区元素将向解复用器提供基于推送或拉取的 srcpad，以便其在下载的文件中导航。

这种模式仅适用于客户端能够确定服务器上文件长度的情况。

在这种情况下，如果请求的范围不在已下载区域 + 缓冲区大小之内，则会像往常一样发出缓冲消息。缓冲消息还会包含正在执行增量下载的指示。此标志可用于让应用程序以更智能的方式控制缓冲，例如使用 BUFFERING 查询。请参阅缓冲策略。

## Timeshift buffering

```json5
      +---------+     +---------+     +-------+
      | httpsrc |     | buffer  |     | demux |
      |        src - sink      src - sink     ....
      +---------+     +----|----+     +-------+
                           V
                       file-ringbuffer
```

在此模式下，系统会使用固定大小的环形缓冲区来下载服务器内容。这样就可以在缓冲的数据中进行查找。根据环形缓冲区的大小，可以查找的时间范围更广。

此模式适用于所有直播流。与增量下载模式一样，缓冲信息会发出，同时还会指示时移下载正在进行中。

## Live buffering

在实时音频流水线中，我们通常会在采集和播放环节之间引入一些固定的延迟。这种延迟可以通过队列（例如抖动缓冲区）或其他方式（例如在音频接收器中）引入。

缓冲消息也可以在这些实时管道中发出，用于向用户指示延迟缓冲情况。应用程序通常不会对这些缓冲消息做出状态更改的响应。

## Buffering strategies

以下是一些基于缓冲消息和缓冲查询的不同缓冲策略的实现思路。

### 无缓冲策略

我们希望在管道中缓冲足够的数据，以确保播放不间断。为此，我们需要知道文件的剩余播放时间和剩余下载时间。如果缓冲时间小于播放时间，我们就可以开始不间断地播放。

我们可以通过 DURATION、POSITION 和 BUFFERING 查询获取所有这些信息。我们需要定期执行缓冲查询来获取当前的缓冲状态。此外，我们还需要足够大的缓冲区来容纳整个文件（以应对最坏情况）。最好将此缓冲策略与下载缓冲结合使用（参见下载缓冲）。

代码如下所示：

```c
#include <gst/gst.h>

GstState target_state;
static gboolean is_live;
static gboolean is_buffering;

static gboolean
buffer_timeout (gpointer data)
{
  GstElement *pipeline = data;
  GstQuery *query;
  gboolean busy;
  gint percent;
  gint64 estimated_total;
  gint64 position, duration;
  guint64 play_left;

  query = gst_query_new_buffering (GST_FORMAT_TIME);

  if (!gst_element_query (pipeline, query))
    return TRUE;

  gst_query_parse_buffering_percent (query, &busy, &percent);
  gst_query_parse_buffering_range (query, NULL, NULL, NULL, &estimated_total);

  if (estimated_total == -1)
    estimated_total = 0;

  /* calculate the remaining playback time */
  if (!gst_element_query_position (pipeline, GST_FORMAT_TIME, &position))
    position = -1;
  if (!gst_element_query_duration (pipeline, GST_FORMAT_TIME, &duration))
    duration = -1;

  if (duration != -1 && position != -1)
    play_left = GST_TIME_AS_MSECONDS (duration - position);
  else
    play_left = 0;

  g_message ("play_left %" G_GUINT64_FORMAT", estimated_total %" G_GUINT64_FORMAT
      ", percent %d", play_left, estimated_total, percent);

  /* we are buffering or the estimated download time is bigger than the
   * remaining playback time. We keep buffering. */
  is_buffering = (busy || estimated_total * 1.1 > play_left);

  if (!is_buffering)
    gst_element_set_state (pipeline, target_state);

  return is_buffering;
}

static void
on_message_buffering (GstBus *bus, GstMessage *message, gpointer user_data)
{
  GstElement *pipeline = user_data;
  gint percent;

  /* no state management needed for live pipelines */
  if (is_live)
    return;

  gst_message_parse_buffering (message, &percent);

  if (percent < 100) {
    /* buffering busy */
    if (!is_buffering) {
      is_buffering = TRUE;
      if (target_state == GST_STATE_PLAYING) {
        /* we were not buffering but PLAYING, PAUSE  the pipeline. */
        gst_element_set_state (pipeline, GST_STATE_PAUSED);
      }
    }
  }
}

static void
on_message_async_done (GstBus *bus, GstMessage *message, gpointer user_data)
{
  GstElement *pipeline = user_data;

  if (!is_buffering)
    gst_element_set_state (pipeline, target_state);
  else
    g_timeout_add (500, buffer_timeout, pipeline);
}

gint
main (gint   argc,
      gchar *argv[])
{
  GstElement *pipeline;
  GMainLoop *loop;
  GstBus *bus;
  GstStateChangeReturn ret;

  /* init GStreamer */
  gst_init (&amp;argc, &amp;argv);
  loop = g_main_loop_new (NULL, FALSE);

  /* make sure we have a URI */
  if (argc != 2) {
    g_print ("Usage: %s &lt;URI&gt;\n", argv[0]);
    return -1;
  }

  /* set up */
  pipeline = gst_element_factory_make ("playbin", "pipeline");
  g_object_set (G_OBJECT (pipeline), "uri", argv[1], NULL);
  g_object_set (G_OBJECT (pipeline), "flags", 0x697 , NULL);

  bus = gst_pipeline_get_bus (GST_PIPELINE (pipeline));
  gst_bus_add_signal_watch (bus);

  g_signal_connect (bus, "message::buffering",
    (GCallback) on_message_buffering, pipeline);
  g_signal_connect (bus, "message::async-done",
    (GCallback) on_message_async_done, pipeline);
  gst_object_unref (bus);

  is_buffering = FALSE;
  target_state = GST_STATE_PLAYING;
  ret = gst_element_set_state (pipeline, GST_STATE_PAUSED);

  switch (ret) {
    case GST_STATE_CHANGE_SUCCESS:
      is_live = FALSE;
      break;

    case GST_STATE_CHANGE_FAILURE:
      g_warning ("failed to PAUSE");
      return -1;

    case GST_STATE_CHANGE_NO_PREROLL:
      is_live = TRUE;
      break;

    default:
      break;
  }

  /* now run */
  g_main_loop_run (loop);

  /* also clean up */
  gst_element_set_state (pipeline, GST_STATE_NULL);
  gst_object_unref (GST_OBJECT (pipeline));
  g_main_loop_unref (loop);

  return 0;
}
```

首先，我们将管道设置为 PAUSED 状态。在预滚动阶段，当需要缓冲时，我们会收到缓冲消息。预滚动完成后（on_message_async_done），我们会检查是否正在进行缓冲，如果没有，则开始播放。如果正在进行缓冲，我们会启动一个超时机制来轮询缓冲状态。如果预计下载时间小于剩余播放时间，则开始播放。
