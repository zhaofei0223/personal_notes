## 001、HTML 转义字符参考

在markdown中有些字符是有特殊意义不能直接在makrdown中显示，需要使用 **HTML 转义字符**替代，目前遇到需要替换如下：

```json5
!    &#33;
?    &#63;
@    &#64;
*    &#42;
$    &#36;
&    &#38;
|    &#124;
\    &#92;
<    &lt;
>    &gt;
空格  &nbsp;
```

## 002、Markdown里如何使用引用

在Markdown中编写引用文字，你可以使用两种主要方法：

1. 使用`>`符号

这是最基本的引用方式。你可以通过在每行前面加上`>`符号来创建引用。例如：

```
> 这是一个引用。
> 这是引用中的第二行。
```

渲染后效果：

> 这是一个引用。
> 这是引用中的第二行。

2. 使用嵌套的`>`符号

如果你想在引用内部再创建一个引用，你可以使用更多的`>`符号来实现嵌套引用。例如：

```
> 这是一个引用。
> > 这是嵌套的引用。
> > > 这是更深层次的嵌套引用。
```

渲染后效果：

> 这是一个引用。
> > 这是嵌套的引用。
> > > 这是更深层次的嵌套引用。

3. 使用列表和`>`符号结合

你也可以在列表中使用`>`符号来创建带有引用的列表项。例如：

```
- 第一项内容
  > 这是第一项的引用。
- 第二项内容
  > 这是第二项的引用。
```

渲染后效果：

- 第一项内容
  > 这是第一项的引用。
- 第二项内容
  > 这是第二项的引用。

4. 使用段落和`>`符号结合（不常见，但在某些情况下有用）

在某些Markdown解析器中，你也可以在段落中使用`>`符号，但这通常不被推荐，因为它可能导致渲染不一致，特别是在不同的Markdown解析器之间。例如：

```markdown
这是一个段落。> 这将不被视为引用，除非在某些解析器中特别支持这种用法。通常，你应该只在单独的行上使用`>`来创建引用。
```

结论：

为了获得最佳兼容性和一致性，建议在单独的行上使用`>`符号来创建引用，并遵循上述第一种和第二种方法。这样可以确保你的Markdown在不同的平台上（如GitHub、GitLab、Bitbucket等）都能正确渲染。
